# 국내 여행 통합 교통정보 확장 조사

확인일: 2026-09-20. `kor-travel-transport`의 목적은 provider 자료를 주기적으로 얻어
자체 PostgreSQL에 저장하고, 외부 요청에는 저장 자료를 즉시 제공하며 내부 통계로
부가 정보를 만드는 것이다. 이 문서는 추가 신청·구현의 우선순위를 정리한 조사이며,
미구현 서비스를 이미 제공한다고 주장하지 않는다.

## 현재 구현과 빈 영역

통합 저장소 `7d1ad37`의 의존성과 `backend/app`을 기준으로 확인했다.

| 영역 | 확인된 구현 | 남은 범위 |
|---|---|---|
| 공항 | 주차 관측·요금·분석·비행편 관련 기능 | 항공편 저장/통계 범위와 전국 지상교통 환승 정보의 별도 점검 |
| 고속도로 | KREX 소통·돌발 주기 저장 및 조회/통계 | 소요시간·예측·CCTV·노선/링크 기준정보·휴게소·보관 정책 |
| 유가 | OPINET Playwright 주기 저장·조회/통계 | 지역 검색 문맥과 소재지의 구분, 과거 중복 UID 병합 손실 평가 |
| 철도·도시철도 | 통합 앱의 KRIC 수집/저장 의존성 없음 | 역사 위치·노선·시간표·편의시설·환승·실시간 도착/중단 |
| 서울 교통 | 형제 `python-seoulgokr-api` 로컬 경로는 존재 | 해당 라이브러리 완성도와 별개로 통합 앱 저장·API 연결은 미확인/미구현 |
| 여객선·유람선 | 통합 앱 수집기/조회 API 없음 | 항구·터미널·기항지·항로·시간표·통제·운임·차량 선적·접근성 |
| 시외/고속/시내버스 | 통합 교통 수집기로 확인되지 않음 | 터미널/정류장, 노선/시간표, 도착정보, 철도·선박 환승 |

## 고속도로: 추가 신청과 provider 개선

KREX `API_COVERAGE.md`는 구현 여부와 live 검증을 구분한다. 이미 사용하는 소통
0405·돌발0611을 신규 미구현 API로 신청 목록에 중복 기재하지 않는다. 기존 키가 모든
추가 서비스에 승인돼 있는지는 계정 화면으로 확인해야 하며, 여기서는 승인됐다고 가정하지 않는다.

| 우선순위 | 신청/확인 대상 | 실제 서비스 가치와 구현 주의 |
|---|---|---|
| 1 | [영업소간 통행시간](https://data.ex.co.kr/guidedown/openoasis_guide.pdf) `odhour/trafficTimeByRoute` | 평균 통행시간을 저장해 소요시간 제공. 속도 평균을 단순 합산한 ETA와 구분. 공식 가이드의 현재 경로·권한을 최소 요청으로 재검증 |
| 1 | [ITS 교통소통·돌발·표준노드링크](https://www.its.go.kr/opendata/intro) | 고속도로 외 국도와 지도 연결 보강. KREX 키가 아닌 ITS 별도 인증·서비스 계약. 서로 다른 링크/구간 ID를 임의 동일시하지 않음 |
| 1 | [ITS CCTV 화상자료](https://its.go.kr/opendata/opendataList?service=cctv) | 좌표와 영상 주소 제공. `type=ex/its`, 영역, `cctvType`, 인증키 필요. URL 메타데이터를 갱신하고 영상 상시 수집/재배포는 허락 범위 확인 전 하지 않음 |
| 2 | [ITS 교통예측·VMS·VSL·주의운전구간](https://www.its.go.kr/opendata/intro) | 출발 시각별 예측, 공사·통제·속도 제한 안내. 예측과 관측을 분리 저장하고 적용 시각을 노출 |
| 2 | KREX 휴게소 시설·주유소·기상 | `route_facilities`, `fuel_prices`는 provider live 검증 기록이 있으므로 먼저 재사용. 통합 저장/조회 연결과 변경 주기 설계가 필요 |
| 2 | KREX 통행료·영업소 기준정보·주차 | wrapper 존재와 live 검증은 별개. 통행료/음식가격은 과거404 기록이 있어 현재 명세 재확인 전 배포하지 않음 |

주의: [국토교통부 교통CCTV 데이터](https://www.data.go.kr/data/3068943/openapi.do)는
위치·설치정보이며 영상 API가 아니다. CCTV라는 이름만으로 영상 제공을 약속하지 않는다.
KREX `reference.routes()`도 전국 노선 마스터가 아닌 작은 로컬 표본이다.

권한 확인은 사용자가 보유한 계정의 신청 목록과 공식 서비스별 승인 상태를 대조한다.
KREX/ITS/공공데이터포털의 키를 서로 대체하지 않는다. 조회 트래픽 계산에는 페이지 수,
대상 지역 수, 재시도와 중복 프로세스까지 포함한다.

개발 한도가 가령 일100회라면 하루 한 페이지를 5분마다 조회하는 것만으로도288회다.
그러므로 **제한 단위를 확인하지 않은 고빈도 운영을 시작하지 않는다.** 승인된 운영 quota를
먼저 확보하고, 한 번의 광역 조회를 DB에서 여러 사용자에게 재사용한다.

위 후보만으로 해결되지 않는 항목은 전국 여객터미널/선착장 좌표·주소·주차·접근성,
차량/자전거 선적 가능 여부, 객실등급·할인 대상별 운임, 예약 잔여석과 실제 승선 마감시각이다.
항만공사·지자체·운항사 자료 및 한국해운조합 안내를 추가 확인해야 한다. 공개 예약 API를
확인하기 전에는 예약 자동화나 잔여석 조회가 가능하다고 표기하지 않는다.
여객선과 관광 유람선, 유·도선은 coverage가 다르므로 한 기관 자료로 전국을 채웠다고 하지 않는다.
항해정보 파일과 운항 스케줄의 식별자 연결은 아직 검증하지 않았다. 코드 대응표를
확보하기 전에는 독립 참조자료로 취급하고 선명·항로명만으로 정원이나 운항 기록을 붙이지 않는다.

## 철도 및 추가 교통정보

KRIC은 [별도 신청 보고서](kric-api-applications.md)를 우선한다. 도시철도 시각표는
열차의 실시간 위치·지연·운행중단과 다르다. 일반/고속철도, 고속/시외버스, 시내버스는
TAGO 등 공식 목록에서 서비스별 조회범위·권한을 추가 확인하는 후속 조사 대상이다.
이 문서에서는 확인하지 않은 서비스 ID나 전국 단일 coverage를 만들어 기재하지 않는다.

여행 효용이 큰 다음 후보는 버스 환승, 역/항구 인근 공영주차장, 전기차 충전기 가동 상태,
무장애 이동시설, 공휴일/행사로 인한 시간표 변경, 도로·해상 기상특보다. 기상만으로
결항/운휴를 판정하지 않고 운항기관의 확정 상태와 예측 정보를 나란히 구분한다.

## 통합 서비스에 필요한 공통 기능

- 기준정보·관측·시간표 유효기간·예측 결과를 분리하고 provider 원본 ID를 보존한다.
  이름이 같은 역·항구·터미널을 자동 병합하지 않는다.
- 조회 응답에는 제공자, 관측시각, 수집시각, 적용기간, 최신성/결측 여부를 노출한다.
  수집 HTTP 성공을 새 관측의 도착과 동일시하지 않는다.
- 페이지·지역별 수집의 완료 범위를 기록한다. 도중 quota/timeout으로 일부만 받으면
  마지막 완전 수집본을 유지하고 새 부분 자료임을 구분한다. 실패나 부분 응답을 근거로
  기존 노선·시설을 삭제하거나 미수집 항목을 폐지로 표시하지 않는다.
- API 응답 경로에서 외부 provider를 동기 조회하지 않고 저장 자료로 응답한다.
  빈 자료·오래된 자료·provider 장애를 구분한다.
- 공급자별 quota 예산·예약·오류 backoff를 유지한다. 실제 재배포 취소는 소통 수집의
  19분 안전 예약 동안 최신성 저하를 만들 수 있으므로 배포 전 진행 중 수집 확인과
  정상 drain 절차를 후속 개선한다. 예약을 임의 초기화해 숨기지 않는다.
- 대량 시계열은 보관 기간·집계·커서 페이지 정책이 먼저 필요하다. 현재 소통 자료의
  증가 추정치는 `docs/tasks.md`를 참고하며, 승인 없이 과거 자료를 삭제하지 않는다.
- 내부 통계는 구간·요일·시간대별 지연 분포, 가격 분포, 운휴 빈도부터 시작한다.
  관측 수·결측률과 분석 기간을 함께 제공하고 적은 표본을 확정 예측처럼 표시하지 않는다.

권장 순서: KRIC 핵심 기준정보/시각표 → 서울 provider 저장 연결 → KOMSA 스케줄과
기항지 기준정보 → KREX 통행시간/ITS 지도 연결 → 교통수단 간 환승·통계.
현재 구현된 기능과 추가 신청이 필요한 후보를 계속 분리해 관리한다.
