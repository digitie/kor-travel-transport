# 교통·날씨 웹 및 Android/iOS 앱 사전 조사

조사일: 2026-10-25(KST). 이 문서는 조사·검토 결과이며 기능 구현이나 운영 수용 보고서가 아니다.
[변경 설계·작업 계획](../design/2026-10-25-mobility-improvements.md)과 함께 읽는다.

## 1. 조사 질문과 확인 범위

화면을 여는 사람이 먼저 내려야 하는 결정, 그 결정을 바꾸는 정보, 사람마다 다른 제약·취향을 조사했다.
기존 admin의 메뉴·조회 흐름은 유지한다. 소비자처럼 검색하고 선택해 보는 경험도 중요한 검증 수단이다.
그 경험에 필요한 데이터가 부족하면 기존 API를 개선하거나 필요한 API를 추가한다.
요청·응답·저장 상태를 매 화면에 전시하는 새 검사 콘솔을 만드는 요구로 해석하지 않는다.

확인 방식은 다음과 같다. 서로 다른 수준의 증거를 같은 것으로 취급하지 않는다.

| 표기 | 확인 방법 | 말할 수 있는 범위 |
|---|---|---|
| 설명 | 운영사 공식 웹 안내·개발자 스토어 설명 | 제공한다고 안내한 기능. 정확도·현재 정상 동작의 증거는 아님 |
| 화면 | 공식 스토어·공식 안내의 화면 이미지를 브라우저에서 확대 관찰 | 정보 배치·표시 문구·보이는 조작부. 실제 탭 이후 동작은 미검증 |
| 후기 | 스토어에 공개된 개별 사용자 리뷰 | 실패 시나리오를 찾는 탐색 자료. 대표성 있는 사용자 조사나 현재 버그 확정이 아님 |
| 코드 | 고정한 저장소 커밋의 경로·호출·조건 대조 | 소스의 구현 사실. 운영 배포·실제 데이터 최신성의 증거는 아님 |
| 사용자 보고 | 이번 대화의 운영 화면·시간표 문제 제기 | 재현해야 할 수용 실패. 원인은 코드·운영 증거로 별도 판별 |

Android/iOS 앱을 설치해 로그인·GPS·결제·알림·실제 승차를 시험하지 않았다. 스토어 양쪽의 기능 설명을
대조했으며, 화면 관찰은 아래에 명시한 자료에 한정한다. OS별 동작·기능 동일성은 추정하지 않는다.
평점·다운로드 수로 UX 품질을 순위 매기지 않았다. 스토어 노출 리뷰는 선택 편향과 오래된 버전의 한계가 있다.

Weather 운영 `/weather`는 로그인 화면까지만 확인했다. 인증 후 지도 치수·운영 릴리스·실제 API 응답은
이번 조사에서 측정하지 않았다. 기존 문서의 fixture E2E 통과를 현재 운영 문제의 반증으로 쓰지 않는다.

### 화면을 보고 확인한 구체적인 패턴

1. 오피넷 Android 지도: 상단 조건, 브랜드+가격 마커, 현 지도 재검색, 하단 후보의 가격·거리·서비스·찾아가기.
   가격과 위치를 왕복해서 확인할 필요가 작다. iOS에도 같은 목적의 화면이 있지만 제스처 동작 동일성은 미검증이다.
2. 오피넷 가격 화면: 유종과 기간을 바꾸며 추이와 최신 숫자를 함께 읽는다. 이것은 평균 유가 화면의 관찰이다.
   사용자 요청인 **개별 주유소·여러 유종의 7일 차트**는 별도의 제품 설계이며 기존 화면에 있다고 주장하지 않는다.
3. 로드플러스 Android 사고 상세: 노선·방향·위치 다음에 주변 CCTV와 구간 상태를 붙인다. 일반적인 전국 통계 나열과 다르다.
4. 코레일+ iOS: 출발/도착과 시각 선택이 주 동작이다. 우리 화면의 큰 역 안내 영역과 따로 노는 시간표 검색을 비교할 근거다.
5. 카카오지하철 iOS: 노선·역, 출구와 하차 위치, 막차 조건을 다른 상세 단계에서 제공한다. 모든 역 메타데이터를 첫 단계에 펼치지 않는다.
6. 날씨알리미 Android: 같은 시간축에 여러 요소를 정렬한다. 좌우 스크롤이 다른 화면 전환으로 오인되지 않도록 해야 한다.

공식 웹의 오래된 앱 안내 이미지는 현재 스토어 이미지와 디자인이 달랐다. 기능 흐름의 근거와 현재 시각 디자인의 근거를 분리했다.
스크린샷의 브랜드 자산·아이콘을 제품에 복사하지 않았다.

### 취향은 필수 조건과 정렬 선호를 구별한다

유종·직원주유 필요·운행 방향처럼 이용 가능 여부를 바꾸는 것은 필수 조건이다. 싼 순/가까운 순,
선호 브랜드, 관심 기상요소, 즐겨찾는 역·장소는 사용자가 바꿀 수 있는 선호다.
‘가장 추천’ 한 가지로 섞으면 싼 대신 먼 곳, 가까우나 반대편 도로, 시설 정보 미확인 같은 이유를 숨기게 된다.
필수 조건으로 0건이 되면 어떤 조건을 풀 수 있는지 보여주고 자동으로 풀지 않는다.
반복 사용을 줄이는 유종·정렬·선호 브랜드·관심 장소 저장은 검토하되 카드번호·상세 이동이력 저장은 필요하지 않다.

## 6. 채택 판단과 후속 조사

우선순위는 **실제로 읽히는 지도와 성공하는 시간표·주차 이력**, 그 다음 **유가 추이와 조건별 후보**다.
그 뒤 접근 가능한 입구·방향·편의시설·관심 요소를 보강한다. 새 항목의 수보다 검색에서 다음 행동으로
끝까지 이어지는지를 본다. 상세 계획의 작업 ID와 수용 시나리오로 연결한다.

자체 통합 여정 플래너·예약/결제·임의 ETA·주차 가능 확률·카드 추천 엔진·사용자 커뮤니티·전국 재수집은
이번 근거만으로 채택하지 않는다. 공식 안내/선호 길찾기 연결은 기존 화면에서 강화한다.

구현 착수 전 남은 조사는 운영 릴리스/실제 지도 치수, TAGO 일반철도와 KRIC 도시철도 각각의 실패 재현,
주차 마지막 정상 run·관측·캐시 watermark, 품질인증 flag와 현재 목록의 의미, 브랜드별 자산 조건이다.
자료 미확보 상태를 기능이 정상 제공되는 것으로 표시하지 않는다. 사용성 가설은 후속 모바일/PC 과제 수행으로 확인한다.
