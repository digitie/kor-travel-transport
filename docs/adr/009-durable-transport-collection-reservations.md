# ADR-009: 교통정보 수집은 짧은 DB 예약과 외부 조회·결과 저장으로 분리한다

- **상태**: accepted
- **날짜**: 2026-09-19
- **결정자**: agent
- **컨텍스트**: 고속도로는 약 5분, 전국 오피넷 화면 탐색은 최소 8시간 주기다.
  두 작업을 같은 트랜잭션에서 실행하면 브라우저 탐색이 고속도로 적재를 지연시키고,
  프로세스 종료 시 수집 시도 기록과 호출 제한까지 롤백된다.
- **결정**: 고속도로와 유가를 별도 task로 실행한다. 짧은 PostgreSQL advisory lock으로
  예정 시각을 확인하고 실행 기록·다음 호출 예약을 원자적으로 commit한다. 외부 조회는
  트랜잭션/DB 연결 없이 실행하고 결과는 새 트랜잭션에 저장한다. 조회 시간 상한은
  고속도로 120초, 전국 유가 2시간이다. 고속도로 임시 예약은 조회 상한+15분이며 전체
  수동 실행에서는 유가 조회 상한을 포함한다. 유가 예약은 provider의 8~12시간 정책이다.
- **근거**: 장기 트랜잭션 대신 DB에 예약을 남기면 여러 backend가 같은 소스를 중복
  호출하지 않으며, 취소/재시작 후에도 호출 예산이 유지된다. 성공 후 고속도로 예정 시각은
  시작 시각+설정 주기로 갱신하고, 유가는 실제 예정 시각까지 대기한다.
- **결과 (긍정)**: 느린 유가 수집이 고속도로 저장을 막지 않는다. 외부 조회 중 DB 연결을
  점유하지 않고, 실패·취소가 발생해도 예약을 유지한다. 무의미한 5분 유가 skip 기록이 줄어든다.
- **결과 (부정)**: 강제 종료된 실행은 `running` 기록이 남을 수 있고 예약 만료까지 재시도가
  지연된다. 실행 예약을 임의로 지우면 호출 제한을 깨므로 운영 중 자동 초기화하지 않는다.
  긴 수집 상한과 예약 여유를 변경할 때는 최악 실행 시간과 DB 저장 시간을 함께 검증해야 한다.
- **후속**: 실제 PostgreSQL의 동시 실행, 취소 후 예약 보존, 외부 조회 중 트랜잭션 부재를
  회귀 테스트로 유지한다. 공개 E2E는 `last_run`만 보지 않고 소스별 최근 성공과 오류,
  실제 저장 데이터까지 검사한다.
