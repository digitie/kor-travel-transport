# 교통 관리자 이용 목적 개선 — 2026-10-24

## 요청 범위와 순서

이 문서는 같은 대화의 1~11번 요청을 이어가기 위한 작업 정본이다.
기존 사용자 변경은 보존하며, 빌드·배포는 사용자가 지정한 다른 에이전트가 합쳐 수행한다.
이 작업에서는 배포용 빌드·운영 배포를 재개하지 않는다.

1. Map Feature 지도의 치수·폰트·배치를 정본으로 common 종류 필터(아이콘 포함), 지도/목록 탭,
   건수+실제 좌표/줌, 지도 위 상세 오버레이를 공용화하여 Map/Transport/Weather에 적용한다.
2. Weather 종류는 특보·실황·초단기·단기·중기·관측으로 구분한다. 특보와 관측을 분리하고
   제공처와 종류를 같은 저장 행에 적용하며 LIMIT 전에 필터링한다.
3. 교통지도 좌표 안내·최근 24시간 돌발 안내·일부 표시 안내 문단을 삭제한다(사용자 6번).
4. 현황을 Map/Weather와 같은 **홈 / 운영 홈**으로 재구성한다. 통합 페이지를 제거한다.
   고속도로·유가는 각각 독립된 운전자 통계 10가지 이상과 상위 메뉴를 갖는다.
   철도/도시철도는 기차, 고속/시외버스는 버스에 묶는다.
5. 철도/도시철도는 노선→역 선택, 역 검색, 큰 지도, 내 근처 역, 이후 시간표,
   편의시설·전화가 중심이다. 운영사·주소는 보조 정보로 축소하고 주소 클릭으로 지도 이동한다.
   KTX/SRT/무궁화 등 열차 종류와 경부선 등 노선 정보·실제 시간표 수집/조회를 개선한다.
6. 버스는 내 근처 터미널, 출발지↔도착지 양방향 연결 후보, 실제 시간표 조회를 제공한다.
7. 비행/공항은 주차장 위치·잔여면과 지금 이후 도착/출발편을 먼저 표시한다.
   과거 주차 패턴으로 주차 가능성을 판단할 통계·DB 조회 성능을 개선한다.
8. 고속도로는 지도와 결합한다. 기존 provider·형제 라이브러리를 먼저 활용하고,
   필요하면 ITS 표준노드링크/SHP 처리 기능은 별도 라이브러리가 소유하도록 한다.

## 검증 원칙

- 수집·시간표 문제가 화면 수정만으로 해결됐다고 표시하지 않는다. 저장값, 실제 조회 응답,
  원천 provider 접근과 최신성·조회 실패를 구분한다.
- 기존 provider 기능을 Transport 내부에 중복 구현하지 않는다.
- 통계는 계산 근거·관측 시각·표본 수를 표시하고 관측이 없으면 추정값을 만들지 않는다.
- 각 단계의 실제 검증과 남은 gate는 `docs/resume.md`와 journal에 기록한다.
