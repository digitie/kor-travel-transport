# 유가 지역 분산 수집 준비

## 상태와 범위

2026-09-29 기준 준비 메모다. 구현·스키마·운영 설정에 아직 적용하지 않았다.
Transport PR #51(`50a1f71`)과 provider PR #20(`7e0f770`)은 머지 완료다.
기존 지도·검색 UI 후속 11개 항목은 별도 백로그이며 완료로 간주하지 않는다.
사용자가 지정한 기존 작업 머지 후 유가 변경 순서를 유지한다.

## 확정된 요구

시간대는 `Asia/Seoul`이며 저장 시각은 UTC를 사용한다.

| 적용 시간 | 시군구 간격 | 최하위 주소 간격 |
| --- | --- | --- |
| 06:00 이상, 20:00 미만 | 무작위 30~120분 | 무작위 2~90초 |
| 20:00 이상, 다음 날 06:00 미만 | 무작위 60~180분 | 무작위 10~120초 |

시군구 순서와 하위 주소 순서 모두 무작위화한다. 과거 야간 3배 규칙은 폐기됐다.
무작위화는 분산 수집 목적이며 제공기관의 차단·인증·요청 한도 우회에 사용하지 않는다.

## 확정된 간격 의미

2026-09-29 사용자가 1번, **지역별 재수집 간격**을 선택했다. 같은 시군구의 수집
완료 후 다음 수집까지 주간 30~120분, 야간 60~180분을 기다린다. 다른 시군구는
그 사이 분산 수집한다. 한 시군구 완료 후 다음 시군구로 이동하기 위한 전역 대기로
구현하지 않는다. 하위 주소 순서와 최하위 주소 간격 요구도 그대로 유지한다.

전국 순회를 보장하려면 처리 용량과 전체 요청 예산을 확인해야 하며, 간격 상한을
모든 지역의 최신성 보장으로 약속하지 않는다. 대기 시간의 경계 통과, 실패 시 다음
지역 진행 여부, 장기 미처리 지역 우선순위는 구현 시 명시하고 테스트한다.

## 현재 코드에서 확인한 제약

- provider `src/opinet/experimental/browser.py`의 `collect_once()`는 새 브라우저로
  전국을 수집한다. `collect_page()`는 지역 전체를 먼저 탐색하고 주유소와 LPG를
  각각 순회한 후 결과를 한 번 반환한다. 지역별 공개 수집·저장 체크포인트는 없다.
- `query_level="sigungu"`가 기본이다. 동 목록을 발견해도 시군구별 검색으로 합친다.
  따라서 현재 동 목록 개수를 동별 유가 검색 횟수로 해석하면 안 된다.
- `query_level="dong"`도 있지만 검색 예산은 지역 수의 두 배(주유소/LPG)로 검사한다.
  동 단위로 변경할 때는 기존 검색 상한 10,000과 예상 호출량을 먼저 대조한다.
  지역 선택·탭 이동 등의 부수 요청도 전체 호출 예산에서 별도로 계산해야 한다.
- Transport `backend/app/services/transport_collection.py`는 `collect_once()` 결과를
  받은 후 주유소와 가격을 저장한다. `_store_fuel_snapshot()`은 개별 조회/저장을
  반복하므로 지역 분할 후에도 DB I/O와 트랜잭션 길이를 측정해야 한다.
- Dagster의 현재 연료 cron은 `0 */8 * * *`다. provider 기본 8시간 간격과 Transport
  예약/실패 유예도 함께 존재한다. cron만 짧게 바꾸거나 보호를 삭제해서는 안 된다.

## 구현 시 지켜야 할 경계

- 지역 발견·부분 지역 검색·파싱·브라우저 종료는 `python-opinet-api`에 구현한다.
  Transport 내부에 같은 provider 기능의 우회 구현을 만들지 않는다. 외부 I/O는 async다.
- 분산 순서와 다음 허용 시각은 PostgreSQL에 영속화한다. 시간은 `TIMESTAMPTZ`,
  provider 지역 코드는 문자열로 유지하고 지역 식별자의 중복을 DB 제약으로 막는다.
  상세 스키마와 migration은 확정된 지역별 재수집 계약을 기준으로 설계한다.
- 짧은 트랜잭션에서 작업을 예약하고 종료한다. 네트워크 호출·랜덤 대기 중 DB 연결과
  잠금을 유지하지 않는다. 오래 잠드는 Dagster job 대신 실행 가능한 작업만 처리하는
  방식을 검토한다. Dagster tick마다 미완료 예약을 다시 발행하지 않도록 한다.
- 가격 저장과 완료 체크포인트는 원자적으로 확정한다. 재시작에도 이미 확정한
  무작위 순서·대기 시각을 다시 뽑아 대기를 단축하지 않는다. 만료된 작업자의 뒤늦은
  결과가 새 예약을 덮어쓰지 않도록 소유권 검증과 중복 저장 방지를 테스트한다.
- 외부 응답 수신 후 DB 커밋 전에 중단되면 재호출 가능성이 있다. 외부 요청의
  정확히 한 번 실행을 보장한다고 쓰지 않는다. 실패 시 보수적 예약 유예를 보존한다.
- 신규 지역은 무조건 즉시 호출하지 않는다. 기존 전국 수집 예약·차단 유예를 인계하고
  기존 cron과 신규 지역 실행의 중복을 막는 전환·롤백 절차를 작성한다.
- 특정 지역 성공을 전국 최신성으로 표시하지 않는다. 지역별 마지막 성공·대기·실패와
  전국 처리 범위를 구분한다. UI 조회는 저장 정보만 읽고 수집 요청을 만들지 않는다.
- 공식 API와 브라우저 수집의 제한을 혼동하지 않는다. 확인되지 않은 호출 예산을
  공식 허용치로 단정하지 않으며 401/403/429·제공기관 유예를 자동 재시도로 우회하지 않는다.

## 검증 계획

- 고정 시계·난수로 05:59:59/06:00/19:59:59/20:00/자정과 간격 양끝을 검증한다.
- 무작위 순서에 누락·중복이 없는지, 재시작/취소/중복 Dagster 실행에 대기 시각과
  체크포인트가 유지되는지 검증한다. 지역 추가·삭제와 동이 없는 시군구도 포함한다.
- 주유소/LPG 결과 합치기, 빈 응답과 장애 구분, 선행 0 코드, 관측 시각·가격 쌍,
  겹친 지역의 같은 UID, 부분 실패 후 성공분 보존을 검증한다.
- 예상 전국 처리량과 외부 요청 수를 네트워크 없는 시뮬레이션으로 산정한다.
  요청 간격만 만족하면서 특정 지역이 영구히 밀리는 설계를 통과시키지 않는다.
- 실제 PostgreSQL에서 동시 예약·만료·오래된 작업자의 저장·원자적 체크포인트와
  migration 왕복을 검증한다. 단위 테스트용 SQLite 결과로 운영 검증을 대신하지 않는다.
- WSL 1차 → WSL+Docker 2차 → 독립 적대 리뷰 2명 → n150 제한 배포와 live E2E →
  CI 확인 후 PR 머지 순서다. 현재 문서는 이 게이트를 통과했다는 증적이 아니다.
- n150 호출은 배포 시점의 실제 유예를 확인한 뒤 명시적인 제한 범위로만 수행한다.
  문서 준비를 이유로 수집을 실행하거나 현재 예약·공용 DB·다른 서비스를 변경하지 않는다.
