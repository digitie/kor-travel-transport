# 기존 교통 관리자 화면의 이용 흐름·공용 지도 개선 설계

상태: **조사에 근거한 후속 구현 계획**. 작성일 2026-10-25(KST).
이번 PR은 문서만 변경한다. UI/API/SDK/DB·Dagster·운영 설정·빌드·배포를 실행하지 않는다.
[웹·Android/iOS 조사와 소스 대조](../research/2026-10-25-mobility-ux.md)가 근거이며, 미확인을 완료로 세지 않는다.

## 1. 유지할 구조와 개선의 기준

기존 홈·고속도로·유가·기차(철도/도시철도)·버스·공항·배편과 운영 메뉴를 유지한다.
소비자가 쓰듯 장소·노선·시간·조건으로 찾고 선택하는 경험을 개선한다. 그 기능이 외부에서도 필요하면
기존 API에 필터·필드·조회 기능을 보완한다. 화면마다 요청/응답 검사 패널이나 새로운 검증 콘솔을 추가하지 않는다.
기존 `/api-test`, 수집 이력, Dagster 화면은 필요한 경우 연결해서 사용한다.

정보 순서는 **지금 할 결정 → 비교 후보·시간별 흐름 → 선택 상세 → 보조 설명**이다.
실패·오래된 값·결측처럼 결정을 바꾸는 상태는 값 가까이에 남긴다. 반복 안내·집계 정의·출처 설명은 제목 옆
이름 있는 `i` 버튼으로 옮긴다. 경고까지 모두 숨기거나 한 화면의 경고를 여러 번 반복하지 않는다.
지표 10개/12개를 채우는 것은 완료 조건이 아니다. 같은 가정으로 만든 운영비 숫자는 후순위다.

## 3. Map에서 재사용할 공용 작업면

정본은 Map `origin/main@c06345841`의 `features-client.tsx`, `admin-shell.tsx`와 Common의 기존
`MapFilterBar`, `MapFilterField`, `MapKindFilter`, `MapTabs`, `MapViewTabs`, `MapReadout`, `MapDetailOverlay`다.
이미 공용화한 부품을 다른 이름으로 다시 만들지 않는다. 추가 공용화 대상은 **이를 묶는 외곽과 높이·상세 슬롯**이다.

```text
기존 admin shell / 간결한 제목 + i + 필요한 행동
  공용 필터: 종류 · 장소 검색 · 데이터 출처 (+도메인 조건)
  공용 지도/목록 전환                  n건 · center 경도, 위도 · z 줌
  하나의 지도 stage
    지도 canvas / 목록 대체 뷰
    상부 요약 슬롯(필요한 페이지에만)
    선택 상세 overlay(동일 stage 내부)
    지도 조작부·범례·attribution
```

도메인 데이터·API·선택 상태는 각 프로젝트가 소유한다. Common은 날씨/유가 요청이나 역 코드 규칙을 알지 않는다.
공용 작업면 확장은 슬롯과 CSS 계약에 한정하고 범용 대시보드 프레임워크로 넓히지 않는다.
Map 소비자는 기존 기능·색상·단축키를 회귀 확인한다. Weather/Transport만 다른 외곽 구현을 갖지 않게 한다.

### 높이·반응형 수용 계약

Map의 `70dvh/min28rem`은 현재 기준선이다. 이것을 그대로 복사하는 것만으로 사용자 요구인 남은 화면 전체 활용을
완료했다고 하지 않는다. compact shell에서 제목/필터/탭을 제외한 실제 가용 높이가 stage에 전달되게 하고,
조상 flex/grid의 `min-height:0`, 단일 스크롤 영역, 지도 `resize`, 브라우저 동적 높이·safe area를 함께 처리한다.
구체적인 공용 컴포넌트 이름은 C-MAP-01 구현 때 기존 exports와 대조해 정한다.

다음은 **새 수용 목표**이며 현재 측정값이 아니다.

- PC 1440×900: 기본 필터 한 줄, Map과 동일한 컨트롤 높이 30px·검색/출처 폭 176px. 긴 종류는 내용에 따라
  명시적으로 감싼다. 지도 하단은 가용 화면 하단과 24px 이내이며 불필요한 이중 테두리·카드 padding이 없다.
- 모바일 375×812·390×844: 키보드가 닫힌 지도 모드에서 stage 시작을 상단 240px 이내로 만들고 남은 높이를 사용한다.
  긴 선택 조건은 간단한 요약과 펼치기로 줄인다. 검색 결과 30개나 통계 카드가 지도 앞을 차지하지 않는다.
- 320×568·가로 화면·글자 200%에서는 지도까지 바로 이동/지도 확장 동작을 제공하고 조작부가 잘리지 않게 한다.
  좁은 폭에 PC 한 줄을 강요하거나 작은 글씨로 압축하지 않는다. 새 페이지 이동 없이 기존 조회를 유지한다.
- 상세는 Map과 같은 stage 안 overlay다. 모바일 기본 상세는 핵심만 보이고 접기/닫기가 가능해야 한다.
  자세히 펼쳐도 지도 제어·attribution·초점을 가리지 않아야 한다. 모바일 배치 정책의 보강은 Common에서 정의하고
  Map도 함께 회귀 확인한다. 프로젝트별 별도 drawer 디자인을 만들지 않는다.
- iOS Safari/Android Chrome의 주소창·키보드·회전, PC Firefox/Chromium의 타일 로드·드래그·선택·뷰 전환을
  확인한다. 토큰이나 내부 URL이 브라우저 번들로 노출되지 않아야 한다.
- `i`, 주소, 브랜드, 닫기 등의 시각 크기는 작게 유지해도 터치 영역 목표는 44px이다. 키보드로 열기/닫기,
  Escape, 초점 반환, 스크린리더 이름, 색 이외의 상태 표현을 확인한다.

색상은 각 앱의 현재 `app/tokens.css`/`design.md`가 정본이다. `--kt-brand/brand-hover/brand-tint`,
`surface-*`, `text-*`, `border/control-line`, `focus`, 상태·그림자 변수를 대응시킨다.
Common 기본 녹색과 프로젝트 navy가 섞이지 않게 light/dark·hover·disabled·popover·차트·메뉴까지 검사한다.
주유소 브랜드 원색, 교통 소통·특보 위험 등 의미가 있는 색은 브랜드 강조색으로 일괄 덮지 않는다.

## 4. 유가 지도와 통계

### 4.1 후보를 찾는 조건

기본 유종·가격순/가까운 순·선호 브랜드를 사용자가 선택하고 다음 방문에도 복원한다.
브랜드 여러 개는 OR, 유종·품질·셀프/직원 조건 사이는 AND로 정의한다. 현재 여러 유종 표시 기능은 유지하되
가격순은 선택한 기준 유종 하나로 정렬한다. LPG/고급유 미취급과 가격 미확인·오래됨을 구분한다.
조건 해제는 명시적으로 하며 결과가 없다고 브랜드·품질 조건을 조용히 완화하지 않는다.

`FuelStation`/상세 DTO에 이미 있는 `brand_code`, `is_self`, `is_24h`, `is_kpetro`, 부대시설을 먼저 재사용한다.
지도 DTO가 문자열 시설만 담는 부분은 typed nullable 필드로 보완한다. 필터는 **LIMIT/클러스터/집계 전에 DB에서**
같은 의미로 적용한다. 마커 일부를 클라이언트에서 걸러 전체 후보·통계를 바꾸지 않는다.
`is_kpetro`의 원천 의미를 확인하기 전 ‘현재 유효한 품질인증’이라고 단정하지 않는다. 필요시 SDK부터 null/미제공과
효력 시점을 보완하고 기준정보에 반영한다. brand·`is_good`·미적발 여부를 인증의 대체 신호로 쓰지 않는다.

카드 혜택은 우선 ‘내가 선호하는 브랜드’ 선택으로 지원한다. 카드번호 입력은 필요 없다.
실효 가격 계산은 대상 유종·결제 방식·실적/한도·적용일의 검증된 조건을 확보한 뒤 별도 선택 기능으로 검토한다.
현재 단계에서 일률 할인이나 카드별 최저가를 자동 추천하지 않는다.
거리 정보는 직선/도로를 명시한다. 도로 연결이 없으면 접근 가능한 경로·우회 시간·순절감액으로 포장하지 않는다.

### 4.2 지도 상부 범위 요약과 주유소 상세

- 범위 요약은 stage 상부의 작은 한 줄/좁은 띠다. 기준 유종, 조건에 맞는 주유소 수, 평균·최저 정도를 먼저
  표시한다. 여러 유종은 짧은 행으로 전환하고 상세 통계는 `i` 또는 통계 페이지로 보낸다.
- bbox·브랜드·유종·출처·검색어·시설 조건의 동일 집합을 집계한다. 마커 limit/클러스터 합계를 모집단으로 쓰지 않는다.
  이전 요청의 응답이 늦게 도착해 다른 bbox 통계에 덮이지 않게 요청 조건을 결합한다.
- 선택 상세의 순서: **브랜드+지점명·닫기 → 최근 7일 유종별 추이 → 현재 유종 가격·시점 → 필요한 시설·길찾기/전화**.
  주소와 출처는 각각 이름 있는 아이콘 popover에서 보되 주소 클릭으로 같은 지도 위치에 초점을 둔다.
  가격의 갱신 지연은 현재 가격 옆에 남긴다. 긴 주소·원본 키·제공처 설명을 여러 줄 상시 노출하지 않는다.
- 차트 x는 실제 관측 날짜/시각(KST 표시), y는 원/L이다. 모든 취급 유종을 구별되는 선/범례와 토글로 표시하고
  각 선 오른쪽 마지막 **실제 관측값**에 가격을 직접 쓴다. 겹치는 라벨은 간격/리더선으로 풀고 색만으로 구별하지 않는다.
  모바일은 동일 데이터를 읽을 수 있는 간결한 표도 제공한다.
- 7일 창에 관측이 없으면 빈 이력, 한 점이면 점이다. 가격 미변동과 실제 수집 실패/미관측을 구별한다.
  원천의 가격 효력 시각·수집 성공 근거가 있을 때만 마지막 확인 가격의 지속 구간으로 표현하고, 근거 없는 구간은
  연결하지 않는다. 기간을 채우려고 과거 값·0원·지역 평균을 만들지 않는다. 현재 가격이 이력 끝보다 새로우면 시각을 구분한다.
- 주유소별 이력은 기존 `FuelPriceSnapshot`과 자연키 이력 export의 조회 로직을 재사용한다. 지역 일별 평균
  `FuelPriceTrend`를 개별 주유소 이력으로 전용하지 않는다. 서비스 토큰 전용 export를 브라우저에 직접 호출하지 않는다.
- 브랜드는 안정적인 코드로 자산 manifest와 연결한다. SK·GS·HD·S-OIL·알뜰 계열·LPG 브랜드별 공식 자산과
  조건을 조사해 원형·비율을 보존한다. 원색 아이콘은 프로젝트 톤 적용 예외다. 이름 없는 일반 펌프만 반복하지 않는다.
  확인 전/알 수 없는 코드는 브랜드명과 기본 아이콘을 제공한다. GS 심벌 단독 제한처럼 실제 조건이 있는 경우
  승인된 전체 조합을 쓰며 임의 crop/재색칠하지 않는다.

### 4.3 통계 화면

`/fuel/statistics`의 기존 지역·유종 선택과 페이지 구조는 유지한다.
첫 영역은 **선택 유종의 최신 평균·전일/주간 변화 + 7일 추이**, 다음은 **지역/브랜드/관심 후보 비교와 분포**다.
각 집계에는 대상 범위·가격 유효 건수·시점이 붙고 분모가 다르면 단순 순위를 만들지 않는다.
같은 조건의 지도 후보로 이동하고 복귀 시 기간·유종·지역 선택을 유지한다.

기존 자료로 가능한 평균·최저/최고·범위·가격 차이·지역별 추이는 재사용한다. 중앙값·분위수·브랜드별 변화·
유효 가격 비율은 실제 이용 결정을 돕고 동일 집합에서 계산 가능한 경우에만 보강한다.
전일/주간 비교의 대응 날짜가 없으면 변화값은 미제공이다. 7일만 보관한 집계로 30일 추이를 그리지 않는다.
월간 필요가 검증되면 보관 기간·비용을 별도 결정한다. 이미 보유한 차량의 실제 지출은 개인 주유 기록 없이는
알 수 없으므로 ‘실제 운영비’라고 부르지 않는다. 기존 50L·연비 계산기는 펼쳐 쓰는 보조 영역으로 이동한다.

## 5. 철도·도시철도 시간표를 끝까지 연결하기

일반철도는 공개 역 안내와 TAGO, 도시철도는 KRIC 저장 시간표라는 서로 다른 경로다. 한쪽의 테스트 성공으로
양쪽이 정상이라고 하지 않는다. 먼저 운영 실패를 구분한 뒤 기존 부품을 연결한다.

| 단계 | 일반철도 | 도시철도 |
|---|---|---|
| 역 찾기 | 노선/차량 탐색과 역명 검색을 병행. 매번 시/도를 먼저 알아야 하는 검색 제한 해소 | 기존 노선·역명·근처 검색 유지. 전국 5000개 선조회/30개 칩이 지도를 미는 구조 개선 |
| 식별 | 공개 역 `station_sequence/station_code`와 TAGO `station_id`의 검증된 연결. 동명이역·이전 명칭 보존 | 운영기관+노선+역 코드를 사용. 기존 자동/수동 crosswalk 재사용, 모호한 역은 분리 |
| 선택 | 지도에서 출발/도착 선택이 실제 시간표 입력으로 전달. 불일치면 재선택할 후보 제시 | 선택 역·노선·방향을 유지하고 이후 예정편을 상세에서 우선 접근 |
| 조회 | date·출발/도착·차량 종류. 기존 catalog/역 목록 사전 조회에 대한 숨은 의존 제거 | 요일/공휴일·달력 유효성, 저장본 존재·48h 신선도·운행 시각 해석 확인 |
| 결과 | 시각·행선지/도착역·차종·소요시간·요금. 지연/잔여석을 제공한다고 주장하지 않음 | 방향별 이후 3~5편·행선지·급행/일반(원천 제공 시), 전체 시간표는 요청 시 펼침 |
| 다음 행동 | 동일 역 지도·전화·공식 안내·현재 공식 예매 경로 연결 | 출입구/전화/편의시설·공식 역 안내, 기존 매핑 관리 화면 연결 |

노선·차량 종류는 별개의 개념이다. 경부선 같은 노선, KTX 등 차량 종류, 현재 운영사 명칭·효력일을
공식 자료와 TAGO catalog로 대조한다. SRT 관련 전환 공지가 있어 예전 문자열을 새 사실로 하드코딩하지 않는다.
연결이 검증되지 않은 차량·역·노선은 검색 보조로만 표시하고 정차/운행을 추정하지 않는다.

API는 합법적인 정상 ID 조회가 다른 사용자의 이전 UI 실행 순서에 좌우되지 않게 한다.
선택한 정상 ID의 참조 검증이 필요하면 제한된 catalog 갱신/저장 절차를 API가 책임지고, 참조 부재·미지원·원천 오류를
구별한다. UI가 별도의 숨은 예열을 해야만 동작하는 계약을 남기지 않는다.
쿼리 `departure_after` 등 이후 시각 조건은 필요하면 기존 시간표 API에 선택적으로 추가하고, 동일 조건을 외부 호출도
사용하도록 한다. KST/offset·운행일·자정/24시 표기를 검증하며 전체 편과 이후 0편을 구별한다.
1000개 첫 페이지만 받고 전체인 것처럼 표시하지 않는다. SDK 페이지 완결/출처 상태를 재사용한다.

KRIC ‘미연결/요일 미확정/미수집/오래됨/정상 0편’은 현재도 구분한다. 문구만 추가하지 말고 끊긴 코드 연결·달력·수집
단계를 복구한다. 화면 새로고침으로 provider를 무제한 호출하지 않는다. 실패 후 정상 저장본 보존·쿼터·재시도 규칙을 유지한다.
출입구·엘리베이터 위치/운영 상태는 별도 데이터다. 수집 범위가 없는 역을 ‘편의시설 없음’으로 표시하지 않는다.

## 6. 고속도로·버스·공항·배편의 후속 범위

**고속도로:** 기존 노선 선택·선형 지도를 유지하고 ‘기본/반대’ 대신 검증된 목적지 방향·IC/JC 구간으로 읽게 한다.
선택 구간의 병목·사고/공사·관측 시각→관련 CCTV/휴게소를 우선 연결한다. 전국 KREX 최근 24h 사고를 선택 ITS
노선의 현재 통제라고 합치지 않는다. 자료가 없는 구간은 회색/미확인이다. 완료 사고는 최신 상태와 관측 시각으로 읽는다.
krits SDK의 사고·CCTV·우회·소요시간 기능을 먼저 검토하고 부족하면 SDK에서 보강한다.
SHP는 선형/ID 결합 공백이 남을 때만 release·좌표계·변환·코드 효력일·조인 성공률을 검증해 채택한다.
주행거리와 구간 평균속도의 단순 평균으로 여정 ETA를 만들지 않는다. 구간 소요시간 비교는 같은 출발·도착/방향·시점에서만 한다.

**버스:** 기존 저장 연결 필터와 전체 검색을 유지하되 연결의 미조회 상태를 구분한다. 출발을 고르면 도착,
도착을 고르면 출발 후보를 갱신한다. 날짜 변경/스왑/검색 취소에 이전 응답이 덮이지 않게 한다.
기간·시외 당일 제한은 provider 계약에 맞춘다. 이후 시각·등급·요금·소요시간과 선택 터미널 위치를 연결하고
좌석 재고가 없으면 예매 가능을 단정하지 않는다. 전국 모든 쌍을 조회해 연결망을 만들지 않는다.

**공항:** 기본 주차·지금 이후 항공편은 이미 있으므로 이를 보존한다. 마중/출국 의도와 항공편 선택으로
해당 터미널·단기/장기 주차와 이동 정보를 우선 정리한다. 취소·회항·실제 도착편을 단순 미래 필터에서 감추지 않는다.
입차 예정 시각의 과거 패턴에는 표본 일수·관측 누락·수용 규모 변경을 표시한다. 항공편 수를 주차 수요로 임의 변환하지 않는다.
최근 7일 주차 시계열은 실제 관측 구간만, 비행편은 기존 하루 0~24시 오버레이에만 표시한다.

**배편:** 기존 항구 선택·항로/터미널/운항편을 연결한다. 시설조사 연도·저장 운항일과 현재 운항/결항 확인을 구분한다.
차량 동반·접근 편의의 추가 정보는 공식 자료에 있는 항목부터 제공하고 미제공은 전화/공식 안내로 이어준다.

실제 행수·쓰기 비용으로 인덱스를 결정한다. 문서만 보고 Timescale 전환·범용 JSON/시계열 체계를 추가하지 않는다.

## 8. 주차 수집·분석 갱신 복구 설계

운영 읽기 전용 점검 순서는 **유효 설정/원천 쿼터 → 기존 schedule/run → 정상 원본 → parking_snapshots 증가 →
파생 cache watermark → 실제 API → 화면**이다. current 최신 여부와 history 최신 여부를 각각 확인한다.
운영 DB 행수·최신 관측/수집·cache 생성/원천 시각, Dagster native run·수집 run 연결을 증거로 남긴다.

소스에서는 `airport_collection_job`/5분 schedule이 이미 있으며, Dagster 수집 op와 in-process/manual 경로의
통계 cache 갱신이 다르다. T-PARK-01에서 재현할 가설이지 운영 원인 확정은 아니다.
`parking/outlook`은 원시 이력의 조회 집계이므로 그 화면이 비면 cache job 추가만으로 해결되지 않는다.

단절이 확인되면 기존 수집의 성공 commit 이후 해당 공항/주차장 분석 갱신을 연결한다.
분석은 provider를 다시 호출하지 않고 저장 관측만 읽는다. 새 관측 watermark 기준으로 멱등 처리하고
실패는 수집 정상분을 롤백하지 않으며 실패 표시·다음 재개가 가능해야 한다. 부분 성공은 성공 공항만 갱신한다.
읽기 경로는 생성 시각만 아니라 원천 관측 시각/요청 범위를 비교해 오래된 cache를 정상처럼 반환하지 않게 한다.
다중 worker의 중복 갱신은 기존 소유권/잠금으로 제한하고 공급자 호출 예약과 별도로 과도한 분석 병렬화를 막는다.

신규 전용 분석 job은 운영 비용·독립 재처리 필요가 입증될 때만 만든다. 원시 관측이 없는 과거는 생성하지 않는다.
backfill은 저장 관측만 범위·배치·재시작 기준을 정해 재집계한다. 같은 요일 표본/공휴일/규모 변경을 섞은
‘주차 가능 확률’은 제공하지 않는다. 운영 활성화·배포는 현재 Manager 정본/ADR-014의 별도 수용 단계다.

현재 캐시 기본값은 `DEFAULT_TIMESERIES_INTERVAL_MINUTES=10`이고, 프로젝트의 최근 7일 화면 요구는 30분 간격이다.
둘을 혼동해 전역 기본값을 바꾸지 않는다. 구현 때 요청 간격을 cache key·생성 범위에 포함하고 30분 표시의 결측·집계를 검증한다.

## 10. 구현 수용 시나리오

1. 위치 허용/거부 각각에서 같은 역·주유소를 찾고, 목록→지도→상세→닫기→외부 길찾기 복귀 뒤 조건·중심·스크롤 유지.
2. 브랜드+유종+품질 조건의 결과, bbox 전체 통계, 마커/클러스터와 API 직접 조회를 동일 입력으로 대조.
   unknown 상태·0건 조건 완화는 명시적 동작이어야 함.
3. 주유소 여러 유종 7일 이력·한 점·중간 공백·최신만 존재·라벨 충돌·늦은 이전 주유소 응답에서 올바른 chart/표 확인.
4. 일반철도 지도 역 선택 후 실제 지원 2개 구간 시간표. cold catalog·차종·날짜·조회 한도·403/429·파싱 오류·일부 페이지와
   도시철도 미연결/미수집/휴일/자정/오래된 저장본을 독립 시험. 합성 fixture만으로 실제 성공을 대체하지 않음.
5. 공항 정상 수집→새 이력→새 cache·outlook→화면을 시각과 run ID로 대조. 부분 실패/같은 관측 중복/분석 실패 후 복구.
   항공편이 현재 주차 수집이나 7일 주차 시계열에 섞이지 않음.
6. 도로 방향 변경·미연결 구간·완료/오래된 사고·CCTV 미제공에서 잘못된 현재 통제나 ETA가 나오지 않음.
7. 버스 출발/도착 스왑·운행일 변경·확인된 연결 0/미조회·타임아웃을 시험. 고속/시외 실제 nonempty를 각각 확인.
8. §3의 화면 크기·브라우저·글자 크기·키보드·초점·토큰/아이콘·반복 멘트를 지도 목록 전부에서 확인.
   외부 API 개선은 같은 사용자 시나리오의 계약/통합 테스트로 검증하고 기존 API-test를 필요시 사용.

기능 구현 PR에는 변경에 맞는 WSL 테스트·Docker 테스트·실제 UI/API 수용·정상적인 리뷰/CI 게이트를 적용한다.
**이번 문서 PR만** 사용자 지시대로 CI 결과를 기다리지 않고, 문서 두 차례 정리 뒤 독립 적대적 리뷰어 1명의 검토로 머지한다.
두 차례 점검과 리뷰 결과는 [검토 기록](../reports/2026-10-25-mobility-design-review.md)에 남긴다.
