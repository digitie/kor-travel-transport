# 유가지도 이력과 공항 주차요금의 실제 동작 보완

## 결정과 범위

사용자는 2026-10-28 실패한 후보의 UI 미완을 유예하지 않고, **전체 UI 수정 후 새 릴리스**로
진행하도록 선택했다. 이전 `3f5160a0`의 UI 실패와 자동 복구 원장은 보존한다. 운영 확정이나
PG18 앱 내부 백업 복구가 완료됐다는 뜻이 아니다. Weather의 완료된 배포는 다시 수행하지 않는다.

이번 보완은 기존 화면 구성을 유지하면서 주유소를 식별하고 최근 가격을 비교하는 흐름과,
선택한 공항 주차장의 실제 저장 요금으로 계산하는 흐름을 완성한다. 관리자 화면에서 사용하는
기능은 같은 공개 API로 외부 소비자도 사용할 수 있게 한다. 별도의 요청·응답 감시 화면을
추가하는 설계로 바꾸지 않는다.

## 유가: 현재 가격을 판단하는 데 필요한 이력

- 지도 마커·목록·상세에 동일한 상표 아이콘을 사용한다. 상표 코드를 우선하며 미확인 코드나
  이미지 오류는 일반 주유기 아이콘과 실제 상표 이름으로 표시한다.
- 오피넷의 [지역별 검색](https://www.opinet.co.kr/searRgOsSelect.do)은 상표·셀프·품질·유종을
  함께 구분한다. 이번 아이콘은 이 공식 코드 연결과 원본 이미지를 사용하며, 이미지의 색상·비율은
  보존한다. 파일별 출처·권리 한계는 관리자 프론트의 `public/fuel-brands/README.md`에 둔다.
- 상세의 현재 가격 위에 최근 168시간의 유종별 관측을 표시한다. 가로축은 날짜, 세로축은 원/L이고,
  오른쪽에는 유종별 마지막 실제 가격을 바로 표시한다. 색 외에 범례·선 모양·관측값 표를 제공한다.
- 관측이 없는 날짜를 만들어 채우지 않는다. 하루 이상 빈 구간은 선을 끊고, 0·음수·결측 가격은
  가격으로 표시하지 않는다. 범례에 마지막 관측 시각을 함께 표시한다.
- 가격 이력의 범위·해석 안내는 제목 옆 정보 버튼에 둔다. 주소·출처 팝업과 기존 지도 상세 오버레이를
  유지하며 장문의 상시 안내 때문에 지도 면적이 줄어들지 않게 한다.

### 공개 API와 데이터 경계

`GET /v1/transport/fuel/stations/{station_id}/price-history`

| 입력 | 계약 |
| --- | --- |
| `station_id` | Feature의 양수 DB ID, 최대 2147483647 |
| `source` | 필수. 현재 `opinet_browser` 저장 이력 지원 |
| `days` | 기본 7, 1~7일 rolling UTC 창 |
| `product` | 선택 유종 코드. 없으면 여러 유종 |
| `limit` | 기본 1000, 최대 5000 |
| `cursor` | 응답의 `next_cursor`를 그대로 사용. 최초 창·필터·수집 revision 고정 |

응답은 `window`, `items`, `latest`, `brand_code`, `brand_name`, `source_last_success_at`,
`source_revision`, `has_more`, `next_cursor`, `meta`를 제공한다. 시각은 UTC이고 화면은 한국 시각이다.
`items`는 실제 창 안의 이력이고 `latest`는 별도 최신 저장 가격이므로 더 오래됐을 수 있다.
차트 우측 숫자는 `items`의 마지막 유효 관측을 뜻한다.

커서는 15분간 유효하며 수집 revision 변경·만료는 409로 처음부터 읽는다. UI는 한 번만 재시작하고
다른 창의 페이지를 섞지 않는다. 선택한 주유소가 바뀌면 이전 요청을 취소한다.
잘못된 입력은 422, 없는 주유소는 404, 이력을 저장하지 않는 원천은 501,
성공한 수집이 없으면 503이다. 빈 관측 배열을 수집 성공이나 0원으로 바꾸지 않는다.

기존 서비스 export의 제한된 DB 조회·커서를 재사용하되 인증 경계를 유지한다. 공개 ID 경로를
추가하기 위해 export의 token·peer 제한을 해제하지 않는다. 관리자 BFF와 공개 gateway에는
이 양수 ID의 읽기 경로만 추가한다. 상세 조회가 원천 수집이나 provider 호출을 유발하지 않는다.
최신 가격도 snapshot의 주유소·원천·유종 연결을 검증해 다른 원천의 포인터가 섞이지 않게 한다.

## 주차요금: 저장 부재와 계산 오류를 구분

공식 출처·기존 저장 커버리지·조사 경과는
[공항 주차요금 실가용성 조사](../research/2026-10-28-parking-fee-policy.md)에 기록했다.

수집 플래그 OFF, 이름이 다른 주차장, 누락된 차량/요일 요금은 서로 다른 상태다. API는
`supported=false`, `reason_code`, `message`, `official_url`로 계산할 수 없는 이유를 전달하고,
UI도 이 응답을 그대로 사용한다. 규칙이 없을 때 임의 요금이나 가장 싼 주차장을 대신 선택하지 않는다.

기존 수집에서 이름 매칭이 안 된 특정 주차장 요금을 공항 공통 규칙으로 저장하던 동작을 막는다.
공식 원천 이름과 실제 주차장 이름의 확인된 연결만 사용한다. 이름 있는 과거 공통 행도 계산에서
제외한다. 차량·평일/휴일 규칙이 모두 있어야 계산하며, 인천에서 제공하지 않는 대형차 요금을
소형차 요금 복제로 생성하지 않는다.

이름 있는 규칙이 전부 또는 일부 미매칭이면 공항별 안전한 오류를 수집 결과에 남겨
`partial_success`로 드러낸다. 정상 주차 관측은 보존한다. `fee_rule_count`는 새 삽입뿐 아니라
실제 저장·갱신한 규칙 수다. 인천은 원천의 기본/추가요금과 양의 일일 최대요금이 완전해야
저장하며, 과거의 일일 최대요금0 행도 무제한 요금으로 계산하지 않고 미가용으로 처리한다.

요금 필드 해석은 형제 `python-krairport-api`의 typed `ParkingFee`에서 보완한다. 실제 필드의
이름·최대요금·무료시간·기본시간·추가시간·차량/휴일별 값을 모델에서 보존하고, 결측과 0을
구분한다. Transport 안에 같은 provider 파싱 wrapper를 새로 만들지 않는다.

### 시간 경계 조사와 계산 검증

[김포공항 공식 주차 안내](https://www.airport.co.kr/gimpo/cms/frCon/index.do?CONTENTS_NO=2&MENU_ID=1360)의
요금표와 계산기를 대조한다. 일일 최대요금의 1일은 입차 시각부터 24시간이며, 무료 회차를
전체 체류시간에서 공제하거나 자정마다 기본요금을 다시 더하는 방식으로 계산하지 않는다.
금요일·주말·법정공휴일의 적용도 확인한다. 경계 사례는 아래와 같다. 표의 가격은 공식 계산기와
대조한 시험 기대값이며 제품 상수가 아니다. 제품은 저장 규칙으로 계산한다.

| 김포 국내선 소형차 입력 (한국 시각) | 공식 계산기 대조값 |
| --- | ---: |
| 2026-11-05 목 09:00 → 2026-11-06 금 09:00 | 20,000원 |
| 2026-11-05 목 23:50 → 2026-11-06 금 00:10 | 1,000원 |
| 2026-11-06 금 09:00 → 2026-11-07 토 12:00 | 36,000원 |
| 목 09:00 → 금 09:05 (24시간 5분) | 20,500원 |
| 최초 10분 / 최초 11분 | 0원 / 1,000원 |

24시간 이후의 짧은 잔여 구간에 최초 기본요금을 다시 붙이는 오류까지 시험한다. 공항별 무료
회차·공휴일·일일 적용이 확인되지 않으면 해당 정책을 지원한다고 추정하지 않는다. 시간대 없는
입출차 입력은 422이고, 할인·실제 정산액은 일반요금 추정과 구분한다.

## 검증과 운영 완료 조건

검증은 소스·모델 시험, 격리된 실제 API/DB/브라우저, 운영 배포 수용을 구분해 기록한다.
로컬 차트 fixture의 성공을 운영 데이터가 준비됐다는 증거로 사용하지 않는다.

1. 형제 라이브러리의 WSL·Docker 시험, 정적 검사, 두 독립 적대적 리뷰와 CI를 통과하고 정확 pin을 반영한다.
2. Transport의 WSL·Docker 백엔드/두 프론트 시험·타입·빌드, OpenAPI 계약과 두 독립 리뷰를 완료한다.
3. Firefox 375/1440에서 실제 선택 주유소의 이력 응답·차트·브랜드 로딩, 지도 높이·오버레이·스크롤,
   키보드·터치·오류·빠른 선택 전환을 확인한다. 응답 전 화면 전환으로 취소된 요청을 성공으로 세지 않는다.
4. 실제 지원되는 주차장과 저장 규칙으로 순수 요금 계산을 확인한다. `supported=false` 응답은
   실패를 감추는 성공 조건으로 바꾸지 않는다. 수집 OFF 상태를 알려주는 UI 시험과 실제 계산 성공 시험은 별개다.
5. 새 release의 정상 배포·원래 수집일정 복구 후 자연 관측 두 번과 정기 `airport_collection_job SUCCESS`,
   주차 네 뷰·분석 갱신을 확인한다. 실제 PG18 앱 내부 백업도 한 번 확인한다.

주차 원본 48시간·통계 영구보존 요구는 유지한다. 영구 reader 전환·backfill·coverage·복원 검증 전
원본 삭제는 계속 차단한다. 철도 지도→시간표 연결/역 편의시설과 Weather 특보 정합 등 별도 남은
기능을 이번 유가·요금 수용과 혼동하지 않는다.
