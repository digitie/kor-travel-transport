# PR #52 운영 오류 후속 수정

## 조사 결과와 계약

- 항구 749개의 저장 이름·코드는 TAGO 원문과 일치했다. 시간표 연결 키의 고아 행은 없었다.
  동명 항구는 9쌍이다. 동명만으로 지역이나 같은 항구라고 추정하지 않고 코드로 선택·조회한다.
  동명 항구의 선택/해제/결과 제목에는 코드와 지역 미확인을 표시한다. 모든 항구 상세와
  시간표에는 코드를 표시하며 API `port_name`은 기준정보에서 조인해 반환한다.
  링크의 알 수 없는 항구 코드를 이름으로 대체하지 않고 오류를 표시한다.
- 배편은 항구별 10일 선점 때문에 호출 예산 뒤의 항구가 누락됐다. 오늘의 모든 항구를 먼저
  보충하고 다음 운항일로 넘어간다. 최대 280회·현재 호출 간격·실패 예산은 그대로다.
  작업 성공은 전국 적재 완료가 아니다. 미수집을 운항 없음으로 표시하지 않는다.
- 버스 시간표는 메모리 15분 캐시뿐이었다. `0016` DB 저장본을 도입해 호출 보호와 키 설정
  문제에서도 같은 노선·날짜·등급의 저장본을 제공한다. 오류를 정상 빈 결과로 저장하지 않는다.
- 고급유는 가격 NULL 행의 존재만으로 판매로 판정하던 문제였다. 유종별 최신 수집 행의
  가격이 양수일 때만 해당 필터에 포함한다. 이전 양수 행이 최신 NULL을 되살리지 않는다.
- 지도는 휴게소와 최근 24시간 돌발 저장 관측을 별도 유형으로 표시한다. 돌발의 각 식별자에서
  최신 행을 먼저 정한 후 좌표·검색 조건을 적용한다. 관측 시각/처리 상태를 표시하며 현재
  진행 중인 사고만 반환한다고 주장하지 않는다.
- 자기부상 6역은 공식 파일에 경위도가 뒤바뀌어 지도 좌표가 NULL이었다. provider PR #10의
  검증된 6행 보정만 소비한다. KRIC API의 CRS 미확정 좌표는 변환하지 않는다.
- KAC ODCloud 상세 조회가 등록되지 않은 서비스 오류를 반환했다. 공식 대체 등록은
  [15158625](https://www.data.go.kr/data/15158625/openapi.do),
  `https://apis.data.go.kr/B551178/flight-status`다. `/depart` 한 건 진단은 HTTP 403이었다.
  키의 새 서비스 활용 승인/접근 상태와 새 provider 연동은 미해결이다. 오류를 정상 빈 시간표로
  표시하지 않는 UI 회귀는 수정했다. 주소만 바꾸면 안 되며 페이지와 필드 계약도 달라진다.

## 검증 이력

2026-09-29 로컬 진행 중 기록이며 운영 통과 증적이 아니다.

- WSL/Docker 관리자 단위 118개, 타입·린트·Next 16 빌드 통과.
- 로컬 HTTPS 브라우저 회귀 61개 통과: 동명 항구 모바일/PC 코드 연결, 고급유 양수 가격,
  휴게소/돌발 상세, 호출 보호 후 버스 저장 조회, 항공편 오류와 빈 결과 분리 포함.
- 백엔드 WSL 관련 19개, PostgreSQL 관련 4개 통과. 이후 버스 갱신 실패 테스트를 더했으므로
  최종 전체 검증은 별도로 실행한다. 전용 PostgreSQL의 `0016 upgrade`/`alembic check` 통과.
- KRIC provider PR #10 WSL 169개·live opt-in 2개 제외, 커버리지 91.52%, 타입·컴파일 통과.
  CI Python 3.11/3.12/3.13·타입 모두 통과. 두 독립 리뷰 P0/P1 없음. P2 위도 변경 및 XLSX
  숫자 셀 왕복 파싱 테스트를 보강했다. 공개 파일 opt-in live 1개 통과, 소비자 live는 대기다.
- 최초 실패도 보존한다: 테스트 venv의 과거 editable checkout이 선택돼 새 `port_name`을
  읽지 못한 실행은 검증에서 제외했다. 이후 `PYTHONPATH`를 현재 backend로 명시했다.
  로컬 HTTPS 시작 시 공개 origin 누락으로 로그인 403 발생 후 환경만 수정했다.
  항구 오류 테스트의 alert 선택자가 Next route announcer까지 포함해 실패한 것은
  실제 오류 문구를 표시하는 `p[role=alert]`로 한정했다. 재실행 61개 전체 통과.
- 전체 회귀에서 새로 추가했던 고속버스 날짜 제한이 기존 API 계약과 충돌하는 2건을 발견했다.
  DB 저장 기능과 무관한 날짜 제한을 제거해 기존 고속버스 계약을 유지한다. 시외버스 오늘 제한과
  관리자 UI의 10일 선택 범위는 기존대로다. 원래 회귀 테스트의 기대값은 바꾸지 않는다.
- Popper의 사전 리뷰에서 provider `ValidationError`를 422로 노출하던 버스 경로와,
  배편 예산 소진 뒤의 저장된 미래 시간표를 미수집으로 집계하던 문제를 재현했다(6개 실패).
  검증 오류에는 원시 값을 숨긴 502 또는 기존 저장본을 반환하고, 배편은 외부 요청만 멈추되
  전체 저장 범위 집계는 마친다. 수정 후 관련 WSL 28개 통과.
- 새 전체 WSL 실행은 로컬 `/tmp` tmpfs 여유 약 2 GiB로 백업 안전 기준에 걸렸다.
  백업 단독 재현으로 확인했으며 실행을 중단했다. 다른 프로젝트를 삭제하지 않고 전용
  `/home/digitie` 임시 디렉터리를 지정해 최종 후보를 다시 검증한다.

## 배포 전 필수 조건

1. 현재 dirty 후보는 미배포다. 기존 API `91262cc`, UI `1558a01` 운영 검증은 신규 수정의
   검증을 대체하지 않는다. PR #52 Draft와 머지 보류를 유지한다.
2. 최신 전체 WSL·Docker·PostgreSQL·CI, 최종 후보에 대한 James/Popper 독립 리뷰가 필요하다.
3. `0016` 적용 전 현재 운영 원본과 DB 백업, 스키마 호환 되돌림 이미지를 준비한다.
   기존 API는 정확한 `ALEMBIC_HEAD=0015`를 요구하므로 단순 이전 이미지 교체는 실패한다.
   추가 테이블을 유지한 채 돌아갈 수 있는 기존 기능 + `0016` 호환 이미지를 별도 검증한다.
   신규 저장본을 지우는 downgrade를 운영 자동 rollback으로 쓰지 않는다.
4. 실행 중 Dagster 작업이 끝난 안전 구간에서 API/code-server만 제한 교체한다. daemon 재개,
   parking-radar·공유 DB·포트·인증 불변을 확인한다. 72시간 관찰 중 prune 금지를 지킨다.
5. 자기부상은 저장 raw를 새 provider로 재파싱해 대상 6행을 대조한 뒤 필요한 좌표만 갱신한다.
   원본은 보존하며 이 작업 때문에 KRIC API를 조기 재호출하지 않는다.
6. n150 실제 지도·저장 API·전체 관리자/parking-radar E2E 이후에만 머지를 판단한다.
