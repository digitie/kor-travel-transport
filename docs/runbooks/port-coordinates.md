# 항구 좌표 정정과 기항지 API

## 원인과 연결 범위

해양수산부 항만가이드라인 파일 `15121268`의 첫 항로 안내 점은 승선 장소가 아니다.
RustFS 파일 보관은 유지하지만 지도 대표점으로 사용하지 않는다. TAGO 터미널 주소에도
인천→여수, 통영→군산 등 불일치가 있어 자동 지오코딩 근거로 쓰지 않는다.

[KOMSA 기항지 정보 15142297](https://www.data.go.kr/data/15142297/openapi.do)의 비동기
`python-kric-api.get_port_calls(name, province)`를 사용한다. TAGO/KOMSA 코드는 서로
다르므로 코드 동일 조인·부분 이름 검색·`항` 문자 일괄 삭제를 하지 않는다.
명시한 TAGO 코드·이름과 시도를 확인하고, API 이름/시도 정확 일치가 한 건일 때만 저장한다.
중복·동명·잘린 응답은 대표점을 만들지 않는다.

초기 대상은 `PORT_CALL_TARGETS`의 주요 항구 19개다. 지역 배정은 명시 검토 목록이며 API
일치 결과 전에는 검증 완료가 아니다. 전체 749곳의 좌표를 해결한 것이 아니다. 섬의 동명
항구·별칭·국제항구는 미확인으로 남긴다. 기존 항로 안내 점은 지도 API에서 즉시 제외하고
다음 기준정보 upsert에서 좌표 필드만 비운다. 항구 ID와 저장 시간표는 삭제하지 않는다.

## 저장과 호출 보호

- 기존 PostgreSQL 테이블을 유지한다. 기항지 코드·지역·좌표는
  `ferry_ports.raw_item_json._komsa_port_call`, 조회 필터·응답 후보·선택 결과·확인 시각은
  `raw_api_responses`에 보존한다. 원본 API 파싱은 provider 라이브러리에서만 한다.
- `last_seen_at`은 기준정보 갱신 시각이다. 좌표의 재확인 시각은 원본 응답의 `received_at`이다.
- maritime 정기 job에 연결하고 지도/목록 조회에서는 외부 API를 부르지 않는다.
- 개발계정 안내 100회/일보다 낮은 80회/최근 24시간 내부 상한을 적용한다.
- PostgreSQL transaction advisory lock `420052`로 예산 검사·예약을 원자화하고 호출 전
  커밋한다. 실패·취소·프로세스 종료도 예산에 포함한다. 네트워크 대기 중 DB 잠금은 없다.
- 성공/빈 결과는 30일, 실패/미완료 예약은 1일 캐시한다. 키와 인증 URL/예외 원문은 저장하지 않는다.
- 제공자 한도 오류를 한 번 받으면 같은 서비스의 다른 항구도 최근 오류로부터 24시간
  신규 요청을 유예한다. 기존 성공 캐시는 계속 읽는다. 유예 건수는 수집 요약과 Dagster
  실패 메타데이터에 표시하며 신규 실패가 없더라도 유예가 남으면 `partial_success`다.
- 일시 실패로 기존 검증된 좌표를 지우지 않는다. 신규 호출 실패는 성공분 저장 후
  `partial_success`로 남기고 Dagster도 자동 재시도 없는 실패를 표시한다.
- 정상 재조회가 빈 결과·중복·지역 불일치·부적합 좌표로 끝나면 이전 좌표와 출처를
  해제한다. 단, 별도로 검증한 VWorld 시설 좌표는 KOMSA 무결과만으로 해제하지 않는다.
  이 결과를 30일 캐시에서 재사용할 때도 동일하다. 실패·호출 유예와 구분한다.

## 후속 확대

### VWorld 장소 검색 보강 (`0017`)

KOMSA 기항지로 확인되지 않은 항구와 좌표가 없는 TAGO 고속·시외버스 터미널은
`python-vworld-api`의 비동기 장소 검색으로 별도 보강한다. 항구는 원본 이름과 정확히
일치하는 단일 `항만시설 > 페리/해운` 검색 결과만 채택한다. 터미널은 이름·시설 분류·
시도가 맞는 단일 결과만 채택한다. 업체·버스정류장·섬 중심점·동명 다중 결과·검색
페이지 누락은 채택하지 않는다. VWorld 시설 점은 실제 승선 지점을 보장하지 않으므로
API와 관리자에 별도 출처와 주의 문구를 표시한다. TAGO와 VWorld의 코드를 동일하다고
가정하지 않는다.

매일 04:30 KST Dagster 작업이 좌표가 없는 기준정보를 보강한다. API/지도 조회 중에는
검색하지 않는다. 사용자 제공 30 TPS 허용 정보를 기준으로 내부 상한은 25 TPS·
최근 24시간 2,000회로 설정했다. 호출 전 receipt 예약·PostgreSQL advisory lock
`420053`·최소 0.04초 간격을 사용한다. 이 상한은 VWorld 공식 quota 확인 결과가 아니라
운영 보호값이며, 요청은 단일 순차 스트림이라 실제 처리량은 응답 시간에 좌우된다.
성공/무결과는 30일,
실패/미완료는 1일 재조회하지 않는다. 위치 미확인 항구·버스 터미널은 목록에서
이름/코드로 검색할 수 있으나 지도에는 표시하지 않는다. `VWORLD_API_KEY`와
`PLACE_LOCATION_COLLECTION_ENABLED=true`를 n150의 비추적 `.env.server14`에
설정해야 실행된다. 실제 좌표 건수는 배포 후 별도로 확인한다.

2026-09-29 운영 저장본 기준 항구 749곳 중 위치 확인 10곳·미확인 739곳이다.
미확인 중 이름에 `_`가 있는 곳 292곳, `_` 없이 괄호가 있는 곳 24곳,
둘 다 없는 곳 433곳이다. 전체 이름 중복 9그룹을 제외하면 이번 엄격 검색의
항구 후보는 429곳이다. TAGO 고속 453곳·시외 350곳은 좌표가 모두 없고,
고속 453곳의 `city_name`은 전부 비어 있다. 동명·복합 이름 보류를 제외한
검색 후보는 고속 372곳, 시외 348곳으로 전체 1,149곳이다. 내부 2,000회/24시간
상한은 이 후보를 한 배치에서 한 번씩 조회하기에 충분하지만, 요청 시간·외부 오류에
따라 실제 소요시간은 달라진다. 이는 검색 시도량의 계산이지 좌표 확보 예상 건수가 아니다.

2026-09-29 첫 운영 수집은 19회 중 정상 응답 14회(좌표 연결 10개·무결과 4개),
한도 오류 5회였다. 이후 위 서비스 전체 유예를 추가했다. 명목 일일 허용량은 같은 키의
다른 소비량을 보장하지 않으므로 한도 오류 뒤 추가 호출로 시험하거나 카운터를 초기화하지 않는다.
전체 749개 항구 중 공식 좌표 10개, 미확인 739개다. 기준정보·시간표 ID는 유지한다.

무인증 [KOMSA 항로 파일 15126739](https://www.data.go.kr/data/15126739/fileData.do)은
2023-08-17 자료다. 확인한 CSV 28,422행 중 기항지명이 있는 행은 4,983행/316개 원문 이름이다.
일반 변침점을 항구로 쓰면 안 된다. 지역·코드 교차표를 확보한 후 별도 provider parser와
RustFS 저장으로 확대한다. 현재 PR은 이 파일의 연결 완료를 주장하지 않는다.
