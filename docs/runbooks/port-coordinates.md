# 항구 좌표 정정과 기항지 API

## 원인과 연결 범위

해양수산부 항만가이드라인 파일 `15121268`의 첫 항로 안내 점은 승선 장소가 아니다.
RustFS 파일 보관은 유지하지만 지도 대표점으로 사용하지 않는다. TAGO 터미널 주소에도
인천→여수, 통영→군산 등 불일치가 있어 자동 지오코딩 근거로 쓰지 않는다.

[KOMSA 기항지 정보 15142297](https://www.data.go.kr/data/15142297/openapi.do)의 비동기
`python-kric-api.get_port_calls(name, province)`를 사용한다. TAGO/KOMSA 코드는 서로
다르므로 코드 동일 조인·부분 이름 검색·`항` 문자 일괄 삭제를 하지 않는다.
명시한 TAGO 코드·이름과 시도를 확인하고, API 이름/시도 정확 일치가 한 건일 때만 저장한다.
중복·동명·잘린 응답은 대표점을 만들지 않는다.

초기 대상은 `PORT_CALL_TARGETS`의 주요 항구 19개다. 지역 배정은 명시 검토 목록이며 API
일치 결과 전에는 검증 완료가 아니다. 전체 749곳의 좌표를 해결한 것이 아니다. 섬의 동명
항구·별칭·국제항구는 미확인으로 남긴다. 기존 항로 안내 점은 지도 API에서 즉시 제외하고
다음 기준정보 upsert에서 좌표 필드만 비운다. 항구 ID와 저장 시간표는 삭제하지 않는다.

## 저장과 호출 보호

- 기존 PostgreSQL 테이블을 유지한다. 기항지 코드·지역·좌표는
  `ferry_ports.raw_item_json._komsa_port_call`, 조회 필터·응답 후보·선택 결과·확인 시각은
  `raw_api_responses`에 보존한다. 원본 API 파싱은 provider 라이브러리에서만 한다.
- `last_seen_at`은 기준정보 갱신 시각이다. 좌표의 재확인 시각은 원본 응답의 `received_at`이다.
- maritime 정기 job에 연결하고 지도/목록 조회에서는 외부 API를 부르지 않는다.
- 개발계정 안내 100회/일보다 낮은 80회/최근 24시간 내부 상한을 적용한다.
- PostgreSQL transaction advisory lock `420052`로 예산 검사·예약을 원자화하고 호출 전
  커밋한다. 실패·취소·프로세스 종료도 예산에 포함한다. 네트워크 대기 중 DB 잠금은 없다.
- 성공/빈 결과는 30일, 실패/미완료 예약은 1일 캐시한다. 키와 인증 URL/예외 원문은 저장하지 않는다.
- 제공자 한도 오류를 한 번 받으면 같은 서비스의 다른 항구도 최근 오류로부터 24시간
  신규 요청을 유예한다. 기존 성공 캐시는 계속 읽는다. 유예 건수는 수집 요약과 Dagster
  실패 메타데이터에 표시하며 신규 실패가 없더라도 유예가 남으면 `partial_success`다.
- 일시 실패로 기존 검증된 좌표를 지우지 않는다. 신규 호출 실패는 성공분 저장 후
  `partial_success`로 남기고 Dagster도 자동 재시도 없는 실패를 표시한다.
- 정상 재조회가 빈 결과·중복·지역 불일치·부적합 좌표로 끝나면 이전 좌표와 출처를
  해제한다. 단, 별도로 검증한 VWorld 시설 좌표는 KOMSA 무결과만으로 해제하지 않는다.
  이 결과를 30일 캐시에서 재사용할 때도 동일하다. 실패·호출 유예와 구분한다.

## 후속 확대

### VWorld 장소 검색 보강 (`0017`)

KOMSA 기항지로 확인되지 않은 항구와 좌표가 없는 TAGO 고속·시외버스 터미널은
`python-vworld-api`의 비동기 장소 검색으로 별도 보강한다. 항구는 원본 이름과 정확히
일치하는 단일 `항만시설 > 페리/해운` 검색 결과만 채택한다. 터미널은 이름·시설 분류·
시도가 맞는 단일 결과만 채택한다. 업체·버스정류장·섬 중심점·동명 다중 결과·검색
페이지 누락은 채택하지 않는다. VWorld 시설 점은 실제 승선 지점을 보장하지 않으므로
API와 관리자에 별도 출처와 주의 문구를 표시한다. TAGO와 VWorld의 코드를 동일하다고
가정하지 않는다.

매일 04:30 KST Dagster 작업이 좌표가 없는 기준정보를 보강한다. API/지도 조회 중에는
검색하지 않는다. 사용자 제공 하루 1만 회·100 TPS 정보를 기준으로 내부 상한은 100 TPS·
최근 24시간 10,000회로 설정했다. 호출 전 receipt 예약·PostgreSQL advisory lock
`420053`·수집 실행 전체의 PostgreSQL advisory lock·최소 0.01초 간격을 사용한다.
중복 Dagster 실행은 건너뛴다. 이 상한은 현재 키의 공식 quota 확인 결과가 아니라
운영 보호값이며, 요청은 단일 순차 스트림이라 실제 처리량은 응답 시간에 좌우된다.
같은 키를 사용하는 다른 서비스의 요청은 이 저장소의 카운터에 포함되지 않으므로,
제공기관 총량은 VWorld 키 관리 화면에서 별도로 확인해야 한다.
같은 장소 ID라도 원본 이름이 바뀌면 검색어가 같아도 기존 검색 receipt를 재사용하지 않는다. 정상 응답·무결과는
30일, 실패·불완전 페이지는 1일 재조회하지 않는다. 호출 예산 소진·불완전 페이지는 부분
성공으로 표시한다. 단발성 네트워크 오류는 해당 호출 실패로 남기고 다음 후보를
진행하지만 인증·한도·기타 제공기관 오류는 배치를 중단한다. 위치 미확인 항구·버스 터미널은 목록에서
이름/코드로 검색할 수 있으나 지도에는 표시하지 않는다. `VWORLD_API_KEY`와
`PLACE_LOCATION_COLLECTION_ENABLED=true`를 n150의 비추적 `.env.server14`에
설정해야 실행된다. 실제 좌표 건수는 배포 후 별도로 확인한다.

2026-09-29 운영 저장본 기준 항구 749곳 중 위치 확인 10곳·미확인 739곳이다.
미확인 중 이름에 `_`가 있는 곳 292곳, `_` 없이 괄호가 있는 곳 24곳,
둘 다 없는 곳 433곳이다. 전체 이름 중복 9그룹을 제외하면 이번 엄격 검색의
항구 후보는 429곳이다. TAGO 고속 453곳·시외 350곳은 좌표가 모두 없고,
고속 453곳의 `city_name`은 전부 비어 있다. 동명·복합 이름 보류를 제외한
검색 후보는 고속 372곳, 시외 348곳으로 전체 1,149곳이다. 내부 10,000회/24시간
상한은 이 후보를 한 배치에서 한 번씩 조회하기에 충분하지만, 요청 시간·외부 오류에
따라 실제 소요시간은 달라진다. 이는 검색 시도량의 계산이지 좌표 확보 예상 건수가 아니다.

2026-09-29 운영 기준정보를 DB 저장 없이 VWorld로 전수 검색했다. 동일한
이름·시설분류·시도 매칭을 적용한 1,149건의 결과는 다음과 같다.

| 종류 | 조회 | 좌표 매칭 | 무결과 | 모호·불일치 | 불완전 페이지 |
|---|---:|---:|---:|---:|---:|
| 항구 | 429 | 33 | 321 | 71 | 4 |
| 고속버스 터미널 | 372 | 45 | 285 | 41 | 1 |
| 시외버스 터미널 | 348 | 107 | 158 | 80 | 3 |

첫 시험은 53번째 요청에서 일시적인 `VworldNetworkError`로 중단됐다. 네트워크 오류에
한해 최대 2회 재시도하고, 연속 10회 오류 시 중단하는 전수 재시험은 1,149건을 모두

건수가 아니다.** 운영 저장본은 여전히 항구 10곳·버스 터미널 0곳이다. 전부 저장되면
이 세 종류의 좌표 보유는 총 195/1,552곳(12.6%)이며, VWorld만으로 남는 1,357곳은 다른 공식
교차표·주소/시설 자료 또는 수동 확인이 필요하다. VWorld 시설 점은 실제 승선 부두나
버스 승차 홈을 보장하지 않는다.

당시 사용한 별도 진단 스크립트는 운영 수집기의 24시간 호출 장부 밖에서 같은 키를
사용할 수 있어 제거했다. 재검증은 운영 장부와 키 전체 사용량을 합산하는 경로가
준비되기 전까지 수행하지 않는다.

### 카카오맵 키워드 검색 보완

[키워드 장소 검색 API](https://developers.kakao.com/docs/ko/kakaomap/rest-api#search-by-keyword)의
단일 장소명·시설 카테고리·시도 검증을 통과한 시설 좌표만 보강한다. 첫 결과 페이지
15건이 전체가 아니거나 `total_count`가 불완전하면 좌표를 선택하지 않는다. 항구의
섬 이름과 실제 선착장 이름이 다른 경우(예: 추자도와 신양항)는 자동 추론하지 않는다.
카카오 시설점도 실제 승선 부두·버스 승차 홈을 보증하지 않는다.
추가 페이지가 필요한 45건은 좌표 보류 수로 집계하되 제공기관 장애로 기록하지 않으며,
하루 뒤 다시 평가한다. 인증·한도·네트워크 오류는 별도 실패로 기록한다.

2026-09-29 운영 기준정보 1,149개에 DB 변경 없는 실제 조회를 수행했다.
최종 수집기와 같은 1페이지·엄격 매칭 기준의 결과는 다음과 같다.

| 종류 | 조회 | 좌표 매칭 | 무결과 | 이름·분류·지역 불일치 | 추가 페이지 필요 |
|---|---:|---:|---:|---:|---:|
| 항구 | 429 | 123 | 147 | 140 | 19 |
| 고속버스 터미널 | 372 | 14 | 120 | 227 | 11 |
| 시외버스 터미널 | 348 | 9 | 38 | 286 | 15 |
| 합계 | 1,149 | 146 | 305 | 653 | 45 |

별도 전체 페이지 시험에서는 1,216회 호출로 156곳이 매칭됐지만, 현재 1페이지
수집기의 자동 적재 예상치는 146곳이다. 146곳과 VWorld 185곳에는 중복이 있으므로
합산하지 않는다. 순서대로 운영 적재한 뒤 실제 순증가를 보고한다. 두 진단 모두
서비스의 호출 영수증 장부 밖에서 키를 사용할 수 있어 재실행 스크립트는 저장소에
남기지 않았다.

[카카오 공식 쿼터](https://developers.kakao.com/docs/ko/getting-started/quota)는
전체 API 월 3,000,000회와 키워드 검색 일 100,000회를 안내한다. 무료 쿼터는
개발자 계정의 첫 카카오맵 활성화 앱에 한정된다. 이 서비스는 다른 키 소비자를 위한
여유를 남기도록 자체 장부에서 최근 24시간 5,000회·최근 31일 50,000회로
더 낮게 제한하고, 같은 장소·원본 이름·검색어·터미널 행정구역의 성공/무결과는 30일 캐시한다.
429가 발생하면 해당 키의 검색을 24시간 유예한다. 키 값을 저장하지 않는 SHA-256
지문으로 구분해 키 교체 후에는 새 키를 사용할 수 있다. 재실행하거나 다른 장소를
조회해 같은 키의 한도 응답을 반복하지 않는다. 401·403은 현재 배치를 중지하되 키·권한 복구 직후
수동 재실행으로 확인할 수 있다.
다른 서비스의 같은 키 사용량은 이 장부에 포함되지 않으므로 앱 관리 화면에서도
일·월별 사용량을 확인해야 한다. `KAKAO_REST_API_KEY`는 Git 제외 로컬 환경파일과
n150 비추적 `.env.server14`에만 저장하고, 운영 실행은
`KAKAO_PLACE_COLLECTION_ENABLED=true`일 때 06:30 KST Dagster job으로 수행한다.

명목 일일 허용량은 같은 키의 다른 소비량을 보장하지 않으므로 한도 오류 뒤
추가 호출로 시험하거나 카운터를 초기화하지 않는다. 운영 좌표 확보 실적은 배포·수집 후
별도로 기록한다.
전체 749개 항구 중 공식 좌표 10개, 미확인 739개다. 기준정보·시간표 ID는 유지한다.

무인증 [KOMSA 항로 파일 15126739](https://www.data.go.kr/data/15126739/fileData.do)은
2023-08-17 자료다. 확인한 CSV 28,422행 중 기항지명이 있는 행은 4,983행/316개 원문 이름이다.
일반 변침점을 항구로 쓰면 안 된다. 지역·코드 교차표를 확보한 후 별도 provider parser와
RustFS 저장으로 확대한다. 현재 PR은 이 파일의 연결 완료를 주장하지 않는다.

### 기준정보 직후 보강과 관리자 좌표 보정

항구·버스 기준정보 Dagster job은 적재가 끝나면 기존 VWorld, Kakao 좌표 보강 수집기를
순서대로 실행한다. 기존 04:30·06:30 독립 job도 남겨 중복 실행이 잠금·receipt·일/월 예산을
통과하지 못하도록 한다. 좌표가 없는 공식 행만 검색하며 지도 조회는 제공기관을 호출하지
않는다. 한 제공기관의 부분 성공도 다른 제공기관의 보강을 막지 않고 마지막에 Dagster 실패로
드러낸다.

관리 UI 지도 페이지의 목록 보기에서 공식 항구·버스터미널 코드로 검색해 장소를 선택하고,
우측 `좌표 수동 보정`에서 위도·경도·확인 근거를 저장한다. 신규 장소 생성 기능이 아니며
공식 ID·제공자 코드·출처가 일치하지 않으면 거부한다. 한국 영역(위도 32~39.5,
경도 124~132) 밖도 거부한다. 수동 좌표에는 `admin_manual` 출처와 마지막 보정 근거·
시간·이전 좌표를 `raw_item_json._manual_location`에 남긴다. 이는 최신 보정의 메타데이터이며
전체 변경 이력 테이블은 아니다. 동일 공식 코드·이름·지역의 다음 기준정보 적재나 KOMSA
재조회가 수동 좌표를 덮어쓰지 않는다. 공식 이름이나 지역이 바뀌면 수동 좌표를 해제하고
재확인을 요구한다. 열린 화면이 오래돼 다른 관리자의 보정이나 수집 결과와 달라졌다면
이전 이름·지역·좌표·출처·수동 수정 버전을 비교해 409로 거부한다. 같은 좌표를
다시 저장하며 확인 근거만 바꾸는 충돌도 거부한다. 코드 자체가 삭제·변경되면 새 공식
행은 다시 확인한다.

쓰기 요청은 관리자 세션과 exact origin 확인을 거친 별도 Next.js BFF만 전달한다.
공개 API gateway는 이 POST 경로를 허용하지 않는다. backend와 관리 UI에 서로 같은
32자 이상 `TRANSPORT_ADMIN_WRITE_TOKEN`을 비추적 운영 환경파일로 전달해야 저장 기능이
활성화된다. 최초 n150 토큰 설정은
`scripts/set-transport-admin-write-token.py`를 n150에서 한 번 실행한다. 기존 환경 파일을
0600 권한으로 별도 백업하고 토큰 값은 출력하지 않는다. 관리자 로그인 아이디·비밀번호의
초기값은 변경하지 않는다. 토큰을 문서·로그·
응답에 남기지 않는다. 관리자 스택 배포 전에 backend의 내부
`/v1/transport/admin/place-locations/capability`에 같은 토큰을 보내 계약 일치를 확인한다.
운영 E2E는 존재하지 않는
공식 ID를 보내 404의 정확한 응답으로 BFF·토큰·backend 연결을 비파괴적으로 검증한다.
이는 정상 저장·DB 왕복 검증을 대신하지 않는다. 사용자는 실제 승선 부두·승차 홈을
운항사에 확인해야 한다.
