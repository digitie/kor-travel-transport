# 자동 역 연결 미리보기 UI

## 범위와 의존

Backend PR152의 `875ed9ab657c600b8b42b63c9457d24ac056a1e1` 위에 쌓은 관리자 UI 변경이다.
미리보기/적용은 저장된 공식 역 코드와 기준 역만 사용하는 API를 소비한다. Backend·SDK·DB·수집·
의존성·전역 스타일은 수정하지 않았다. 운영 미리보기/적용, provider 호출, 시간표 수집·복구,
운영 이미지 빌드·배포는 실행하지 않았다. 이 문서의 fixture 성공은 운영 성공이 아니다.

기존 검색·역 선택·수동 편집·JSON 내보내기를 유지했다. 도구 모음의 `자동 연결 미리보기`가
기존 Base UI 기반 Dialog를 열고 공식 역 코드 기준의 전후 건수·실제 변경행·수동 충돌·
차단 사유만 표시한다. 설명은 제목 옆 i에 두며 요청/응답 JSON 패널·추가 확인 모달은 없다.
표시색과 팝업 표면은 기존 `info-popup`을 재사용하고 레이아웃만 해당 팝업에 한정했다.

## 계약과 상태 보호

- BFF `GET/POST /api/admin/rail-station-mappings/automatic`은 관리자 세션, 내부 토큰,
  POST origin·JSON·본문 상한을 검사하고 `no-store, private`를 사용한다.
- 적용 POST는 미리보기의 `expected_revision`, `candidate_revision` 두 값만 보낸다.
  수동 `mappings`/`note` 또는 다른 필드는 BFF에서 거절한다. 기존 수동 API는 유지한다.
- `can_apply && has_changes`를 서버 값대로 사용한다. `has_changes=true`와 effective
  `changes=[]`·전후 동일 건수는 수동 연결이 자동 후보를 억제한 정상 경계다. 이를
  `연결 대상 변경 없이 자동 후보를 갱신합니다`로 표시하고 충돌과 함께 적용을 허용한다.
- 방법만 바뀐 행은 같은 대상의 전후 연결 기준을 표시한다. `applied`와
  `changed_link_count=0`은 정상일 수 있다. 완료 문구의 실제 역 연결 건수는 FK 변경 수이며
  후보 갱신이나 시간표 복구 건수로 바꾸지 않는다.
- 수동 대상·근거 초안이 변경됐거나 수동 저장 중이면 자동 미리보기를 막는다. 저장 중
  편집 입력과 중복 저장을 막고, 자동 적용 중에는 돌아가기·적용·바깥 클릭·Escape 닫기를
  막는다. 완료 뒤 기존 검색과 필터, 아직 필터 안에 남아 있는 선택을 유지하며 목록을 다시 읽는다.
  선택 역이 필터 밖으로 바뀌면 기존의 첫 보이는 역 선택 동작을 따른다.
- 적용 전 돌아가기/닫기는 POST0이다. 전송된 POST의 fetch 취소나 화면 unmount는 서버의
  DB 원복을 보장하지 않는다. 결과 확인 실패는 후보를 폐기하고 새 미리보기에서 현재 상태를
  확인하도록 안내한다. 409도 자동 재시도 없이 새 미리보기를 요구한다. 503은 오류로 표시하며
  연결0건으로 바꾸지 않는다.
- 문서 조회와 미리보기는 각각 요청 세대·AbortSignal로 늦은 응답을 무효화한다. 적용/수동 저장
  시작 시 이전 문서 GET을 무효화하고, 닫힌 미리보기나 unmount 후 응답은 반영하지 않는다.

## 검증과 증거

검증 전 최초 미리보기 UI 회귀10개가 실패했고 원본 `red.log`를 보존했다. 이후 초안·수동 저장·
두 revision·409/503·차단/충돌·변경 없음·후보만 갱신·방법 변경0FK·unchanged·검색 보존·
늦은 응답·unmount를 검사했다. 기존 수동 편집과 proxy 회귀도 유지한다.

최종 WSL 관리자 전체314개·타입·lint·Next 빌드가 통과했다. 로컬 WSL Docker Compose의
`run --rm --no-deps`에서도 같은 관리자314개·타입·lint·빌드가 통과했다. Backend 전체는 이 프론트 변경에서
중복 실행하지 않으며 PR152와 자동 CI의 결과를 별도 게이트로 취급한다.

선행312개 Docker 실행이 본인 mirror의 `.next` 일부를 root 소유로 만들어 다음 WSL 타입
검사가 EACCES로 거절된 원본도 보존했다. 본인 경로만 소유권을 복원했고 최종 Docker는 현재
uid/gid로 실행한다. 제품 결함이나 타입 통과로 오인하지 않는다.

375 hasTouch와1440의 로컬 Chromium fixture에서 팝업 크기·가로 넘침·긴 변경 목록의 내부
스크롤·닫기/적용 접근·중첩 i의 Escape 우선·Dialog Escape와 초점 복귀가 통과했다. 적용 중
Escape/바깥 클릭이 닫지 않는지, 409 뒤 사용자가 새 미리보기를 요청하는지, 후보만 갱신하는
0FK 성공도 확인했다. 375 팝업은 x12/폭351/높이349.48,1440에서는 폭672/높이333.48이다.
375 닫기/적용은 높이44.39px이며 긴 목록에서도 본문만 스크롤하고 닫기가 화면 안에 있다.
가로 넘침·페이지 오류·차단된 외부 요청·실제 backend 요청은0이다. 로그아웃303/인증쿠키0과
context/browser·소유 Next 서버/자식 종료를 확인했다. 합성 QA 쿠키를 사용한 fixture이며 실제 로그인/운영 API/DB 검증이 아니다.

증거는 `/var/tmp/codex-rail-automatic-ui-20261027`에 둔다. 선행 `ui-render`는 불변 보존하고
최종 화면은 `ui-render-final`에 구분한다. 원본 로그·PNG·source/package/lock manifest와
소유 서버·브라우저 종료 증명은 최종 receipt에 연결한다. 정식 CI·두 독립 적대 리뷰·PR152
머지 뒤 main retarget·최종 같은 소스 게이트·운영 검증은 부모 에이전트가 별도로 정산한다.

## 독립 리뷰 후 편집기 복구·재조회 보호

위314개/`ui-render-final`은 최초300193a 후보의 증거다. 독립 James 리뷰에서 수동409 뒤
dirty가 새로고침을 막는 문제와 자동 적용 뒤 GET 대기 중 새 초안이 지워지는 P1을 발견했다.
추가3회귀를 기존 소스에서 실행해3FAIL/17PASS로 재현한 뒤 수정했다.

수동 대상/근거 초안이 있을 때만 `초안 취소 후 새로고침`을 제공한다. 사용자가 누르면 초안을
명시적으로 폐기하고 최신 revision을 읽는다. 이 버튼은 POST하지 않으며 작업면으로 초점을
옮겨 사라지는 취소 버튼에 초점이 남지 않게 했다. dirty 중 일반 새로고침/자동 미리보기 보호는
유지하고 자동 재저장·확인 모달은 추가하지 않았다.

문서의 준비 상태를 별도로 관리해 자동 적용 성공과 같은 렌더부터 후속 GET 완료까지 편집·
저장·역 선택·검색/필터 변경을 잠근다. GET 실패 후에도 옛 revision 편집을 허용하지 않으며
기존 오류에서 최신 목록 확인이 필요함을 알리고 사용자 새로고침 성공 때만 해제한다.
저장 중이라는 문구와 문서 조회 중인 상태는 구분한다. 명시 취소 경로의 GET이 실패해도
일반 새로고침으로 다시 읽을 수 있다. 요청 세대·AbortSignal·전송된 POST의 결과 한계는 유지한다.

수정 후 WSL/Docker 관리자 전체317개·타입·lint·Next 빌드가 각각 통과했다. 추가 상태의 실제
375/1440 렌더링은 `ui-render-review-r4`에 구분했다. deferred GET 편집/선택 잠금, GET503 뒤
편집 금지와 새로고침 복구, 수동409의 초안 유지→명시 취소→최신 revision 재저장, 취소의
POST0/초점 복귀가 통과했다. 팝업 크기·기존 Escape/충돌·0FK 수용도 유지됐다.

`ui-render-review-r2/r3`의 첫 화면검증 실패는 Next의 숨은 route announcer도 role=alert라서
검증 locator가2개를 찾은 문제다. 원본을 보존하고 r4에서 매핑 작업면 내부의 같은 오류
단언으로 범위를 명확히 했다. 제품 오류를 숨기거나 단언을 완화하지 않았다. 소유 서버와
브라우저는 종료했고 운영/provider/DB 접근은 없는 fixture다. 실제 로컬 통합은 새 정확
소스의 별도 DB/API 수용 영수증과 구분하며 과거300의 r4 통과로 대체하지 않는다.
