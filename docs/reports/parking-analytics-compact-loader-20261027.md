# 공항 주차 분석의 원본 조회량 축소

성능 비교의 원본은 `6d243c4982beafda6c893fac7107e3193e356d85`다. 실제 변경은 최신
`main`의 `d7c36c3c99dafdefe4bc0100fd797662a2b4afd3`를 포함해 검증한다. 범위는 공항
주차 분석 캐시와 캐시가 없을 때 사용하는 기존 분석 API의 관측 조회에 한정한다. API 응답
구조, 분석 기준, DB 스키마·인덱스, 수집 일정, 제공자 SDK 의존성은 바꾸지 않는다.

## 실제 관측에서 드러난 문제

운영 제품 `7f01b0133dad73843ce61444830b1020cfd32f0a`의 자연 수집을 읽기 전용으로
확인했다. 첫 수집의 원본 저장 구간은 약 25.43초였으나, 원본 저장 완료부터 Dagster
종료까지 약 530.85초가 더 걸렸다. 다음 자연 수집도 원본 저장은 약 15.51초,
이후 종료까지 약 395.59초였다. 이 파생 계산 지연은 5분 수집 주기보다 길다.

첫 모바일 조회의 HTTP 504·30.012초 실패와 이후 성공은 별개의 관측이다. 이후
모바일 HTTP 200도 약 6.028초가 걸렸으며, 초기 실패를 해소된 것으로 지우지 않는다.
전체 232개 캐시는 한 시점에 모두 10분 유효기간을 넘겼다. 상세 원장과 원본 실패는
[운영 수용 보고서](https://github.com/digitie/kor-travel-transport/blob/0d9bbdcae5ca3ba648e9083668ef2e72457dad28/docs/reports/2026-10-26-parking-production-rollout.md)에 보존한다.

이 문서의 합성 측정은 운영 성능 개선 완료 증거가 아니다. 새 제품 배포 뒤 실제 자연
5분 수집의 종료·캐시 갱신과 모바일 최초 조회를 다시 확인해야 한다. 과거 수집 중지
구간의 관측을 복구하거나 채웠다는 의미도 없다.

## 원인과 수정

기존 캐시는 공항 전체와 각 활성 주차장마다 7일·14일·14일·21일 관측을 별도로 읽었다.
각 조회가 `ParkingSnapshot` 전체 ORM 객체와 계산에 쓰지 않는 `raw_item_json`까지
전송하고, Python에서 중복을 제거했다. 주차장별 계산이 동일 공항의 원본을 반복해서
가져오므로 범위와 관측 수가 늘어날수록 전송·JSON 해석·ORM 생성 비용이 중복됐다.

수정은 다음 범위에 한정한다.

- 공항별로 최대 21일과 기존 10분 완충 구간의 계산용 값만 한 번 읽는다. 공항 전체와
  주차장별 계산은 같은 관측을 재사용하고, 각각의 기존 시간 창을 적용한다.
- 중복 선택은 SQL `row_number`에서 처리한다. `migration_`로 시작하는 소스보다 실제
  소스를 우선하고, 같은 우선순위에서는 `collected_at`·`id`가 큰 관측을 선택한다.
  `migrationX`의 `X`를 SQL 패턴의 와일드카드로 처리하지 않는다.
- DB가 반환하는 관측은 식별자·공항·주차장·관측 시각·잔여·점유·전체 면수의 7개
  필드다. 소스와 수집 시각은 DB 내부 순위 계산에만 사용하며 원본 JSON은 조회하지 않는다.
- 이벤트에는 기존과 같은 주차장 이름·공항 이름을 명시적으로 결합한다. 공항 전체
  통계는 비활성 주차장 과거 관측을 유지하고, 개별 캐시는 활성 주차장에만 생성한다.
  관측 없는 활성 주차장도 네 종류의 빈 결과를 유지한다.
- 기존 API의 시간대·요일·특수일·임계치와 시계열 조회도 같은 계산용 조회를 사용한다.
  주차장이 지정되면 공항보다 우선하는 범위 선택, 한국 날짜 경계, 날짜 사이의 조회
  공백을 유지한다. 응답 DTO와 OpenAPI는 바꾸지 않는다.

`generated_at`은 첫 원본 조회 전 시각을 유지한다. 10분 유효기간, 새로 적재된 오래된
관측에 의한 캐시 무효화, 원본 저장 후 분석의 별도 트랜잭션, 분석 실패 롤백,
수집과 공유하는 PostgreSQL advisory lease도 유지한다. 완료 시각으로 watermark를
이동하거나 유효기간·요청 timeout을 늘려 지연을 숨기지 않는다.

## PostgreSQL 동일 데이터 비교

합성 관측은 공항 2개·전체 주차장 8개·관측 있는 주차장 6개·활성 주차장 6개,
총 분석 범위 8개다. 21일간 5분 간격에 긴 수집 공백·비활성 이력·관측 없는 주차장과
실제/이관 소스 중복을 포함한다. 총 35,696행이고, 행마다 사용하지 않는 JSON 문자열
4,096자를 넣었다. `parking_snapshots`의 인덱스·TOAST를 포함한 relation 크기는
214,818,816바이트였다. 운영 데이터를 복제하거나 제공자 API를 호출하지 않았다.

WSL2의 전용 PostgreSQL 16과 Python 3.12.13을 사용했고 DB는 이 시험만의 별도 이름과
네트워크 namespace로 격리했다. 계산 컨테이너는 CPU 1개·메모리 2GiB, DB 컨테이너는
CPU 1개·메모리 768MiB였다. 원본→수정→수정→원본 순서로 측정하여 한 번의 순서에만
의존하지 않았다. OS·DB 캐시는 강제로 비우지 않았으므로 실제 운영의 최초 조회 시간이나
보장된 지연 상한으로 해석할 수 없다.

| 항목 | 원본 1회 | 수정 1회 | 수정 2회 | 원본 2회 |
| --- | ---: | ---: | ---: | ---: |
| 전체 캐시 계산·저장 시간 | 6.212초 | 0.970초 | 0.945초 | 5.216초 |
| 관측 관련 SELECT 수 | 40 | 10 | 10 | 40 |
| 실제 관측값을 읽은 SELECT 수 | 32 | 2 | 2 | 32 |
| 원본 JSON을 포함한 SELECT 수 | 32 | 0 | 0 | 32 |
| 계산 Python 프로세스 최대 RSS | 235,196KiB | 88,044KiB | 87,740KiB | 235,264KiB |
| 생성한 캐시 행 | 32 | 32 | 32 | 32 |

최대 RSS는 해당 Python 프로세스의 `resource.getrusage(RUSAGE_SELF).ru_maxrss`다.
DB 서버·컨테이너 전체·운영 호스트의 메모리 사용량을 뜻하지 않는다. 관측 관련 SELECT에는
범위별 최신 관측 시각의 `MAX` 8회도 포함되며, 이 기존 metadata 조회는 제거하지 않았다.

네 번 모두 32개 캐시의 전체 payload와 범위·분석 인자·생성 시각·원본 관측 시각이
정확히 같았다. 정렬된 JSON 952,797바이트의 SHA-256은 모두 다음 값이다.

```text
0035c86f9fb854d6e326c6f0c9dd4b245c850f79d19a3e0751be2e38eadab71e
```

비교한 `analytics_cache.py`의 LF 기준 SHA-256은 원본
`ecf8dcab50a64602b545bc765bd13bf483d20f848b1645ed01cddbc8ba986ac7`, 수정
`064f75f7f3889743219b5384ca3b1e0d2946f6cfd071a87a76a86a73d7ca60fa`다.

## 회귀와 재현

[집중 회귀](../../backend/tests/test_parking_analytics_compact.py)는 원본 ORM·Python
중복 제거를 독립 기준으로 사용하여 네 분석 전체를 비교한다. 7·14·21일 경계 전후
1마이크로초와 10분 완충, 한국 자정, 공백과 마지막 관측, 같은 시각의 여러 주차장
이벤트 20개 순서·이름, 실제/이관 우선순위와 수집 시각·ID 동률, 공항 전체·주차장
우선·공항 미지정·특수일 API를 다룬다. 별도 회귀는 첫 조회 이후 시계가 진행해도
처음의 `generated_at`이 바뀌지 않는지 확인한다. 기존 캐시 갱신 회귀도 함께 실행하여
무효화·TTL·부분 수집·분석 실패 롤백·동일 lease 경합을 검증한다.

집중 검증은 SQLite 9개, PostgreSQL 기존 18개와 추가 경계 3개가 통과했다. 기존 API·분석·
캐시의 WSL2 회귀도 85개 통과·PostgreSQL 전용 1개 건너뜀을 확인했다. 원본 코드에
조회량 회귀를 적용했을 때 원본 JSON 조회 단언에서 실패했다. 추가 경계를 포함한
최종 전체 WSL2·Docker·CI 결과와 두 독립 적대적 리뷰의 고정 SHA는 이 변경 PR의 검증
기록에 남긴다. 이 문서의 작성 시점 집중 결과를 최종 전체 검증으로 대체하지 않는다.

재현 도구는 [격리 벤치마크](../../backend/tests/benchmarks/parking_analytics_cache.py)다.
일반 pytest에서 자동 실행하지 않는다. `KOR_TRAVEL_TRANSPORT_TEST_DATABASE=1`,
명시적인 `TEST_DATABASE_URL`, loopback PostgreSQL, 정확한 DB 이름
`parking_analytics_benchmark_test`가 모두 있어야 실행되며 운영 `DATABASE_URL`을
상속하지 않는다. URL query 옵션은 모두 거절한다. SQLAlchemy 연결 인자가 query의
`host`·`database` 등으로 덮이는 경우를 무접속으로 재현하고
[연결 제한 회귀](../../backend/tests/test_parking_analytics_benchmark_guard.py)로 차단한다.
원본 guard에서 거절 회귀의 실패를 확인했고, 수정 후 연결·시계 회귀 16개가 통과했다.
모듈 import는 제품 시계를 바꾸지 않으며, 고정 시계는 명시 실행의 `try/finally`
안에서만 적용하고 성공·예외 모두 원래 함수로 복구한다. import 전후 함수 identity와
시각 불변, 예외 시 복구를 별도로 검증한다. 이 검증은
SQLAlchemy의 연결 인자 변환만 사용하며 DB 접속·외부 제공자 호출은 하지 않는다.
마이그레이션한 빈 전용 DB에서 `seed --out <새 fixture.json>`를 실행하고,
같은 DB와 고정 의존성에서 원본과 수정 코드의 `PYTHONPATH`를 각각 지정해
`measure --out <각각 새 결과.json>`을 실행한다. 결과 파일은 덮어쓰지 않는다.
`measure`는 이 전용 DB의 캐시만 비우고 다시 계산하므로 다른 테스트·운영 DB에는
사용하지 않는다. 원본·수정의 `payload` 전체와 `payload_sha256`을 함께 비교한다.

최종 합성 원본·SQL·전체 payload·요약·해시의 이번 작업 보관 위치는
`/var/tmp/codex-parking-cache-compact.jAZ3av/pg/benchmark-final/`이다. 앞선 진단용
합성 결과는 별도 `benchmark-results/`에 보존하며 최종 수치와 혼합하지 않는다.
운영 읽기 전용 수용의 18개 증거와 SHA 원장은
`/var/tmp/parking-runtime-acceptance-20261026.2YXvOH/candidate-7f01b0133dad73843ce61444830b1020cfd32f0a/`에
보존한다. 비밀 키·인증 URL·운영 DSN·원본 환경 변수는 이 보고서에 기록하지 않는다.
