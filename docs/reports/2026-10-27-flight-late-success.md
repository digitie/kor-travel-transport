# 2026-10-27 — 항공편 지연 성공의 화면 반영

## 문제와 범위

운영 `3691a07ab5bca36060173294c7d02c7399b76e4c`의 실제 Chromium375에서
`flights/status`가 HTTP200·365개 마커를 반환했지만 일별 흐름에는 0개가 남았다.
첫 응답은14.767초, 좁힌 후속 응답은8.981초였다. 후속은 React 분석 로딩이 끝난 뒤에도
항공편 DOM0개가45초의 조건 대기 동안 유지됐다. 이 둘은 원래 실제 실패 증거로 보존한다.
365는 API 마커 개수이며 공동운항 멤버를 펼친 실제 편명 개수와 같다고 주장하지 않는다.

원인은 `useAnalyticsData`가6초에 합성 오류를 확정하고, 이후 같은 요청의 성공을
다시 상태에 반영하지 않는 것이었다. 직접 호출자는 공개·관리자 양쪽이 재사용하는
`AnalyticsView` 하나다. 관리자에서는 `@kor-travel/parking-ui` 파일 의존성으로 같은 소스를 설치한다.
주차 분석 HTTP12.971초는 별도 요청이며 이6초 경계 때문에 버려지지 않았다.
분석 성능과 항공편 결과 소실을 같은 문제로 계산하지 않는다.

## 최소 변경

- 기존6초는 주차 분석 표시를 풀어 주는 시점으로 유지한다. 항공편은 확정0편/오류 대신
  기존 범례 안에서 계속 조회 중임을 알린다. 새 패널·CSS·색상·레이아웃은 추가하지 않는다.
- 같은 항공편 GET 하나를 계속 기다려 최종 결과를 반영한다. 주차 분석보다 항공편이
  먼저 도착해도 이미 얻은 결과를 옛 대기값으로 덮지 않는다. 자동 재시도 GET은 없다.
- 클라이언트 항공편의 최종 상한은 요청 시작부터30초다. 이때 요청을 취소하고 실제 실패로
  표시한다. 관리자 BFF의30초는 응답 헤더 대기 상한이며 본문까지 포함한 클라이언트 상한과
  완전히 같은 시계가 아니다. BFF·서버의 기한/캐시/TTL은 변경하지 않았다.
- 공항·주차장·갱신 세대 변경, 비활성화, unmount 때 이전 효과를 취소한다.
  현재 효과와 선택 범위가 유효할 때만 늦은 응답을 반영한다.
- 유효0편 성공·제공자 오류·네트워크 거절·분석 자체의 오류를 구별한다.
  SDK/백엔드/API wire DTO/수집·저장·요금·인증 계약은 변경하지 않는다.
