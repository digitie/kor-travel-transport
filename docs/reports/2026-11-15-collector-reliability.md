# 수집 반복 실패 원인과 관리자 상세 진단

## 실제 원인

11월15일07:10 KST 직전24시간 Dagster 조회에서 고속도로는91회 성공·141회 실패,

같은 시각 유가는1회 시간 초과 뒤 후속2회 성공이었다. 과거 실패를 지우거나 성공으로 고치지 않는다.

고속도로 SDK의 실제 응답8352행 중 `6000CZS050`/`6000VDS01230` 한 행은 방향이 공백,
등급0·속도-1이었다. SDK가 `FlowDirection('')` 변환을 시도해 전체 응답을 거부했다.
방향은 Optional이고 원천 결측이므로 추정하지 않고 `None`으로 보존한다. 유효한 다른 행을
건너뛰거나 원문 count를 줄이지 않는다. 비어 있지 않은 미지 코드·잘못된 시각·건수 불일치는
계속 실패시킨다.

공급자 PR19의 검증된 제품 `af045fa692c7da9186b5d8adda548aeac99229c7`을 소비한다.
정확 HEAD의 CI43649573614 성공과 두 독립 검토 지적0 뒤 공급자 main
`894ea64faed3a9a0ba9ba11b2a59dc5a0b5e5634`로 머지했다. Transport 내부에 파서 우회를
추가하지 않았으며 `pyproject.toml`·`uv.lock`이 같은 제품 SHA를 가리킨다.

## 재발 방지와 진단 경계

SDK의 부분 파싱 실패에는 원문 값 대신 고정 코드 `TRAFFIC_FLOW_INVALID_RECORDS`와
수신/정상/불량 행 수를 남긴다. 소비자 Dagster에는 실패 단계·수집 범위·오류 코드·복구
정책·재시도 가능 여부·원본/소통/돌발/유가 저장 개수·성공 자료 보존 여부를 안전한
metadata로 남긴다. 기존 source별 성공 commit·호출 예약·보호 유예·유가 checkpoint와
Dagster의 무조건 재실행 금지 정책은 바꾸지 않는다. 재시도 가능은 즉시 재실행을 뜻하지 않는다.

관리자 상세 조회는 선택한 실행만 읽고 원인 체인과 허용한 숫자·분류를 조합한다.
일반적인 run 실패가 상세 step 실패를 덮지 않도록 하며, 인증·origin·코드 위치·run 소유
범위와 페이지/총시간 상한을 유지한다. 원문 예외·URL/query·키·SQL·stack·임의 metadata는
서버 BFF에서 제거한 뒤 브라우저로 전달한다. 전체 목록의 선행 로그 조회는 추가하지 않는다.
수집 상태 화면에서도 실패한 실행의 원인을 요청한 때만 확인할 수 있다.

## 별도 외부 규격 변경

바다허브4원천 중 `official_terminals`만 `SchemaError`이며 마지막 정상 저장본은 유지됐다.
공식 SDK의 공개 다운로드 진단은 DB/정본 archive 쓰기0으로
`공식 파일 CSV 첨부 schema 오류`를 재현했다. 이어 페이지 메타데이터만 읽은 HTTP200에서
자료명/버전은 일치하지만 JSON-LD `distribution`이 없는 것을 확인했다.
첨부 identity 검증을 임의로 건너뛰거나 다른 CSV를 대체하지 않는다.

향후 이 실패는 원천·오류 유형·응답 검증 단계와 고정 코드 `VADAHUB_SCHEMA_CHANGED`로
남긴다. 파일의 실제 규격 수용은 공급자 SDK의 별도 계약 검토가 필요하며 이번 고속도로
파싱 복구로 완료 처리하지 않는다. 유가의 이전 시간 초과도 후속 정기 성공과 구분하고
보호를 무시한 추가 브라우저 수집·무제한 재시도를 하지 않는다.
