# 2026-10-25 — 공항 주차장 관리자 화면에 parking-radar 네 뷰 재사용

## 범위와 경계

사용자 요청은 기존 parking-radar의 모든 조회 화면을 Transport 관리자의 공항 주차장 페이지에서 사용하는 것이다.
`/parking`을 항공·여객선 메뉴에 추가하고 현황·분석·과거조회·요금계산을 같은 페이지의 탭으로 제공한다.
별도 앱의 iframe이나 외부 링크로 화면을 대체하지 않는다. 공개 앱의 `/`, `/analytics`, `/history`, `/fees`는 유지한다.

주차 수집·DB·Dagster 실행·분석 캐시의 정합성 복구는 별도 작업이다. 이 변경에서 운영 수집을 실행하거나
운영 이미지 빌드·배포를 하지 않는다. 아래 브라우저 검증의 통제된 응답과 운영 자료 수용을 구분한다.

## 재사용·설치 경계

- 정본은 기존 `frontend/src`의 뷰·차트·API·context·hook이다. 내부 import를 상대 경로로 바꾸어 두 Next 앱의 `@/` 의미 차이를 제거했다.
- 이 소스 디렉터리를 내부 `file:` 패키지 `@kor-travel/parking-ui`로 노출한다. 공개 앱의 이름이나 별도 라우트는 바꾸지 않는다.
  `files`와 `exports`는 조회 UI·hook·lib·주차 CSS로 한정한다. 앱 라우트·서버 프록시·환경 파일·생성물·테스트는 패키지에 넣지 않는다.
- 관리자의 `.npmrc`는 `install-links=true`다. `npm ci`가 소스를 관리자의 `node_modules`에 복사하고
  React·Base UI·날짜 달력 의존성을 관리자 프로젝트 안에서 해결한다. 공개 앱의 `node_modules`를 설치할 필요가 없다.
  Next는 이 패키지만 `transpilePackages`로 처리한다.
- 관리자 Docker의 기존 루트 빌드 문맥을 유지하면서 의존성 단계에 `frontend/src`와 `.npmrc`를 복사한다.
  런타임은 실제 설치된 패키지를 포함한 기존 관리자 산출물을 사용한다. 운영 이미지는 이번 작업에서 만들지 않는다.
- 기존 뷰 CSS를 한 번만 `frontend/src/parking.css`로 추출하고 `.parking-radar`에 범위를 제한한다.
  공개 앱도 같은 CSS를 사용하며, admin은 그 범위 안에서 navy·명암·테두리·간격 토큰과 컴팩트한 배치를 연결한다.
  전역 테마·다른 지도·다른 페이지의 버튼을 주차 앱 스타일로 덮어쓰지 않는다.

## 인증·요청 경계

관리자는 기존 API client에 명시적 빈 버전 접두어를 주어 `/api/transport/...`를 사용한다.
공개 앱은 계속 `/api/backend/v1/...`를 사용한다. 내부 API 주소나 관리자 비밀값을 브라우저에 전달하지 않는다.

기존 인증 GET 프록시에는 `dashboard/bootstrap`, `dashboard/analytics`, `admin/collector-status`,
`parking/analytics/timeseries` 네 경로만 추가했다. 기존 공항·주차 현황·항공편 경로를 함께 재사용한다.
POST는 `fees/calculate` 하나만 허용한다. 세션·origin·JSON 매체 유형·선언 및 실제 스트림 4KiB 상한을 검사하고
응답 상태·JSON·`no-store, private`를 유지한다. 수집·복원·일반 admin 쓰기 경로는 열지 않는다.

기본 현황에서 분석·과거 시계열·항공편 API를 한꺼번에 부르지 않는다. 화면이 보일 때 15초마다
관측·수집 시각 표지를 확인하고 변경된 경우에만 bootstrap을 갱신한다. 다른 주차 뷰에서 방문한 분석·과거조회는
상태를 보존하되 숨은 동안 재조회하지 않는다. 늦은 응답은 현재 선택을 덮지 않고, 요금 입력을 바꾸면
이미 보낸 계산의 늦은 응답을 폐기한다.

## 재현 후 함께 수정한 기존 오류

1. 활성 주차장 배열이 매 render 새로 생성되어 요금 계산의 두 번째 주차장이 첫 번째로 돌아갔다.
   두 활성 주차장과 차종 변경 테스트에서 수정 전 선택 `3→1` 실패를 재현했다. 배열과 유효 선택을 안정화했다.
2. 로컬 09시를 UTC 문자열로 잘라 `datetime-local`에 넣어 KST에서 기본값이 00시가 됐다.
   WSL `TZ=Asia/Seoul`에서 `T09:00` 기대·`T00:00` 실제 실패를 재현하고 KST 표시·UTC 제출을 분리했다.
   같은 입력의 제출 UTC 시각을 KST·UTC 테스트 환경에서 대조한다.
3. 기존 Tabs의 `data-horizontal` 선택자가 실제 `data-orientation` 속성과 달라 분석 패널이 탭 목록 옆으로 줄었다.
   실제 320px Chromium에서 패널 폭 26px·히트맵 영역 0px을 재현하고 공용 원본의 orientation 배선을 고쳤다.
4. 실제 375px·200% 글자에서 달력이 화면 밖으로 나갔다. 달력 칸 크기를 viewport에 맞게 제한하고
   Portal·기간 선택·닫기·초점을 실제 브라우저에서 재검증한다.

## 검증 상태

WSL2 1차에서 동일한 주차 소스를 대조했다. 운영 API 수용은 별도 담당자의 조회 결과로만 정산하며 아래 통제된 응답 성공과 구분한다.

- 공개 앱: 14파일 137개 단위, 테스트 타입, 프로덕션 웹 빌드 통과. 요금 6개는 KST·UTC 각각 통과했다.
- 관리자 단독 설치: 공개 `frontend/node_modules`가 없는 별도 폴더에서 기본 `npm ci`를 실행했다.
  설치된 공용 패키지가 symlink가 아닌 실제 디렉터리이며, 배포 대상 25파일의 작업 소스·복사 소스·설치 결과가 모두 byte 단위로 같았다.
  `npm pack --dry-run --json`에 앱 라우트·환경 파일·테스트·생성물·`node_modules`가 포함되지 않았다.
- 관리자: 단독 설치 환경의 38파일 280개 단위, 타입·lint 0·프로덕션 웹 빌드 통과.
  PR132 main `1d807fd` 위에 본인 커밋만 재배치한 코드 후보 `4007a9d`에서 main의 추가 2개를 포함한 282개·타입/lint·빌드를 다시 통과했다.
  저장소에 커밋한 단일 설정으로 전체 30개도 이 후보에서 다시 통과했다.
- 실제 Chromium/Firefox: 320·375·414·768·1440px 네 뷰/분석 네 탭, 선택·탭 왕복·요금 POST,
  실패/미지원/빈 관측/실제0, 정상 `airports=[]`의 분석·과거조회·요금 종료, 초기 bootstrap 실패의 허위 pending 해제,
  375px/200% 달력 Portal·10/30/60분·미래 금지·Escape/초점, 공항/주차장 항공편 왕복·운영/정책 안내,
  15초 변경 표지 polling/숨은 분석 fanout 방지, 공개 앱 네 경로를 26/26 통과했다.
- coarse pointer: Chromium·Firefox의 375px 네 뷰와 200% 달력 4/4 통과했다. 필터·새로고침·탭의 44px 실제 높이를 단언한다.
- Turbopack 개발 모드: 같은 관리자 단독 설치에서 `next dev`를 실행하고 `http://localhost:12355`의 375px 네 뷰·분석 네 탭·요금 POST·탭 상태 1개 흐름을 통과했다.
  처음 `0.0.0.0` 바인딩에 `127.0.0.1`로 접속한 실행은 Next의 dev HMR origin 거부로 hydration이 보류됐다. 이 환경 실패를 `evidence/dev-origin`에 보존하고, 허용 origin을 넓히는 코드 변경 없이 localhost로 검증했다.
- 중간의 단순 DOM 통과만으로 최종 수용하지 않았다. 스크린샷에서 잘못 중첩한 CSS 범위 때문에 지표421.95px·SVG stroke 없음이 보였고
  같은 치수/stroke 단언으로 실패를 보존했다. `.parking-admin` 접두어만으로 범위를 제한하고 재검증했다.
  짧은 화면의 모바일 rail173.92px와 768px 메뉴179px도 재현해 기존 지도 페이지의 컴팩트 header/menu 규칙을 `/parking`에 재사용했다.
- 최초 분석 응답을 보류한 단위 테스트로 빈 안내가 먼저 나오는 오류를 재현했다. 성공한 이전 자료는 갱신 중 유지하며,
  최초 로딩·실패에는 빈 자료라고 단정하지 않는다.
- `/tmp` 15GB tmpfs의 공간 부족으로 독립 설치 한 번이 중단됐다. 기능 실패나 통과로 세지 않고 본인 폴더를
  여유 있는 `/home`으로 옮겨 새로 설치했다. 다른 작업자의 파일·프로세스·운영 상태는 변경하지 않았다.

브라우저 검증은 저장소의 `playwright.parking.config.ts`로 재현한다. 관리자와 공개 앱의 로컬 서버를 실행한 뒤

## 독립 리뷰 뒤 공용 달력·갱신 경쟁 보완

아래는 `d6aab36` 이후의 코드 보완이다. 위 137단위/30UI와 부모가 수행한 WSL+Docker의 282/137 통과는
기존 `4007a9d`·동등한 `d6aab36` 소스의 증거로 보존하며 새 코드 수용으로 합산하지 않는다.

- James는 실제 React와 보류한 Promise 순서로 공항 변경 조회 중 focus/15초 poll이 새 관측 표지를 발견하면
  배경 bootstrap이 선택 조회를 무효화하고 `loading=true`가 남는 P1을 재현했다. 작성자도 focus/poll 두 실패를 먼저 확인했다.
  선택 조회의 request ID를 추적하고 그 동안은 상태 확인만 수행한다. 최신 선택끼리의 응답 순서 검사는 유지한다.
  선택 응답이 옛 관측 표지를 가진 경우 다음 상태 확인에서 새 표지를 다시 조회하고, 오류 뒤 수동 재시도도 가능하다.
- 같은 갱신 경계에서 배경 요청 진행 중 focus 세 번에 bootstrap 2회 기대/3회 실제 실패도 재현했다.
  이미 갱신 중이라 돌아온 callback이 다른 요청의 잠금을 풀지 않도록, 자기 요청이 확보한 표지만 해제한다.
- coarse 320px 달력은 오른쪽328.95px 넘침을 재현했다. 7칸×44px를 유지하면서 달력의 coarse 수평 padding만 없애고
  날짜·이전/다음 월 버튼과 캡션의 최소 높이를 맞췄다. 320/375px·100/200%에서 달력 폭308px, 7개 요일·모든 날짜,
  Portal의 상하좌우 viewport 포함과 날짜/월 이동의 CSS44px를 단언한다. Chromium의 변환 rect43.999996px는
  1/1000px로만 정규화하고 CSS 계산값44px도 함께 검사한다. 터치 기준을 낮추지 않았다.
- 기존 실제 QA 기록을 직접 대조했다. Firefox375는 높이812px·coarse·기본 글자/모션이고,
  7일1009버킷에서 첫날144버킷으로 조회했다(첫날 HTTP200/70ms, 빈 응답 아님).
  처음 직접 진입한 900px fixture의 빠른 네 조건은 정상이었다. 이후 같은812px·분석→일별→과거 이동과 스크롤을 맞추자
  Chromium의 기존 좌표 클릭이 `14~20`/`7~20`으로 바뀌는 실패를 재현했다.
  선택 전 `scrollY=31/달력y264`가 결과 제거 뒤 `scrollY=0/달력y295`로 바뀐 원인을 분리했다.
- 달력이 열린 동안만 기존 결과 영역의 실제 높이를 예약한다. 다른 범위의 수치는 계속 숨기고, 첫 응답이 로딩·빈200·오류503이어도
  두 번째 날짜를 고르는 동안 문서 높이가 줄지 않는다. 닫으면 `min-height`를 해제한다. 고정된 상시 빈 공간은 추가하지 않는다.
  이 재현과 Firefox 실제 QA의 ‘두 번째 click은 focus만 됨’을 같은 원인이라고 단정하지 않는다.

이 보완을 합친 소스의 WSL2 공개 앱 14파일142개·테스트 타입·웹 빌드, 관리자 단독 기본 `npm ci` 뒤
38파일282개·타입·lint0·웹 빌드를 통과했다. Chromium/Firefox·coarse 전체34개도 skip/flaky0으로 통과했다.
빠른 선택은 모션 기본/해제×즉시/800ms응답×locator/기존 좌표8조건에, 첫날 빈200·오류503 반영 뒤의 좌표 선택2조건을
각 컨텍스트에서 대조했다. scrollY 유지·`20~21`·닫은 뒤 예약 높이 해제를 포함한다.

## Docker 주기 시험의 실제 시간 의존 제거

부모의 정확한 `7d42d86`·1CPU Docker 실행은 공개 141통과/1실패였다. 실패는 기존 시험이 20ms 간격을
실제 60ms 동안 두 번 이상 실행한다고 가정한 부분이다. 상태 조회는 실제1회였으며 이 결과를 통과로 계산하지 않는다.
작성자 독립 Docker 복사본에서는 원본 13개와 전체142개가 통과했지만, 같은 시험의 대기 구간에 90ms 이벤트 루프
정체를 주입하면 `actual1/expected>=2`가 재현됐다. 제품의 추가 bootstrap이나 잘못된 자료 반영은 관측하지 않았다.

해당 시험 하나만 기본 15초 주기의 가상 시계를 `act` 안에서 30초 진행하도록 바꿨다. 상태 조회 정확히2회와
bootstrap 정확히1회를 검사하며, `finally`에서 화면을 해제하고 잔여 timer를 지운 뒤 실제 시계로 복구한다.
제품 소스·lock·vendor·브라우저 시험은 `7d42d86`과 동일하다. 이전 34UI·개발2개·관리자 단독 설치/웹 빌드는
이 제품 동일성으로 유지하며 불필요하게 재실행하지 않았다.

수정 뒤 WSL2 공개142개·테스트 타입을 통과했고, 작성자의 1CPU/network-none Docker에서도 공개142개·테스트 타입을
통과했다. 원본·정체 주입 실패·제어된 시계 성공 로그는 `/var/tmp/codex-parking-timer-qa-20261025/evidence`에 보존한다.
처음 WSL 설치 모듈을 Docker에서 사용한 시도는 native binding 오류로 시험을 시작하지 못해 결과에서 제외했고,
별도 Docker 설치 모듈을 복사한 독립 시험 폴더에서 위 재현·검증을 수행했다. 부모의 증거 폴더는 수정하지 않았다.
새 최종 커밋의 독립 Docker·CI·두 리뷰·실제 API 수용은 계속 별도 게이트다.
