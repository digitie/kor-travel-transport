# 여행 검색·지도·수집 운영 화면

kor-travel-map의 검색·필터·지도/목록·선택 상세 구조와 kor-travel-weather의
수집 요약·제공기관 상세·최근 실행·스케줄 구조를 transport에 적용한다.
기존 parking-radar와 운영 자격증명은 변경하지 않는다.

## 읽기 계약

- 지도는 주유소/역/항구/공항/휴게소와 출처·유종별 필터를 제공한다. 유가는 주유소·유종별
  최신 관측을 VWorld React `PriceMarker`에 표시한다. 단일 `latest_price`는 휘발유 우선이다.
- `features/places?include_unlocated=true`는 좌표 없는 검색 목록용이다. bbox를 함께
  지정하면 좌표 없는 장소는 제외된다. `source`는 정확한 제공자 코드 필터다.
  `query`와 `product_code`도 서버의 표시 상한보다 먼저 적용한다. `available_sources`는
  표시 상한에 잘리지 않은 종류별 출처 목록이다.
- 지도 계약은 경도 ±180/위도 ±90의 유한한 좌표 쌍만 제공한다. 기본 지도 조회는
  잘못된 좌표를 count/limit 전에 제외한다. 미등록 포함 검색은 장소를 유지하며 좌표만
  `null`로 반환한다. 기존 DB 원본은 수정하지 않고 provider 파서도 다음 수집부터
  범위 밖 좌표를 비운다. UI는 오래된 API 응답도 같은 범위 검사로 보호한다.
- 100px 축척 막대에 해당하는 지상 거리가 30km 이하이면 클러스터를 해제한다.
  종류별 최대 300곳/전체 최대 900곳이며 다섯 종류 기본 요청은 각각 180곳이다.
  잘린 결과와 묶음이 현재 로드한 수라는 사실을 표시한다. 지도 키가 없어도 목록은 읽는다.
- 배편은 항구 최대 5곳/오늘 포함 10일을 `ports/timetables`에서 DB만 읽는다.
  `missing_port_ids`는 미수집, 빈 저장 응답은 결항 확정이 아니다. 변경된 선택의
  늦은 응답을 버리고 실제 저장 확인 시각을 표시한다.
- 기존 `/ports/{port_id}/timetable`은 DB miss에서 provider를 호출한다. 따라서
  429는 초기 한 번이 아니라 다른 미수집 항구를 연속 조회할 때도 발생한다.
  새 검색 UI는 이 경로를 사용하지 않으며, 기존 endpoint의 보호 간격은 유지한다.
- 고속/시외버스는 별도 탭에서 터미널 자동완성 후 명시 버튼으로만 운행편을 읽는다.
  429 보호 시간을 지키고 100편 상한의 부분 결과를 표시한다. 시외버스는 당일만 지원한다.
- 개별 역 마커의 다음 예정 시각은 `rail/departures?place_ids=...`에서 최대 300역을
  한 번에 조회한다. DB 저장본만 읽고 전체 시간표는 응답에 싣지 않는다. 기존 5역 비교
  `rail/timetables` 계약은 유지한다. 화면 영역 밖·묶음·목록 보기·숨긴 탭에서는
  불필요한 다음 예정 요청을 하지 않는다. 60초마다 갱신하고 출발이 지났거나 조회 결과가
  70초 이상 오래되면 시각을 숨긴다. 미연결·미수집·운행일 미확정·48시간 경과를 구분한다.
- 고속버스 출발일을 지우면 빈 값과 조회 비활성화를 유지한다. 버튼을 누르는 순간
  한국 날짜가 바뀌었으면 기존 날짜로 API를 호출하지 않고 날짜 동기화를 안내한다.
- 공항은 저장 주차 관측과 명시적인 출도착 조회, 고속도로는 노선 다중 선택과 돌발 지도다.
- `/collections`는 설정 활성과 실제 성공을 구분한다. 공동 공항 job 성공을 각 provider
  성공으로 오인하지 않으며, Dagster 장애가 있어도 읽을 수 있는 provider 상태를 유지한다.

## 미연결 데이터와 남은 범위

2026-09-27 n150 읽기 점검: 항구 749개, 도시/광역철도 역 1,108개, 버스터미널 803개,
휴게소 0개. PR #42에서 운영 backend에 KRIC 인증키와 48시간 제한 배치를 적용했다.
초기 보호 대기로 인증 코드·시간표·달력은 아직 미수집이다. 다음 열차 UI는 저장본이
확인될 때만 예정 시각을 제공하며 현재 실제 운행편 적재 완료를 의미하지 않는다.
버스터미널 provider 계약은 좌표를 제공하지 않는다. 이들 정보는 임의 생성하지 않는다.
전용 역 코드/시간표 수집 및 터미널 좌표 데이터 연결이 남아 있다.

승인받은 KRIC 키는 Git에서 제외되는 로컬 `.env.kric.local`에 보관했다. 9월 27일
초기 진단 오류는 provider의 실제 `body` 배열 파싱 누락이었다. provider PR #7로
수정하고 역사정보 34행/휴일 시간표 344행을 확인했다. 배포 뒤 인증 재호출 대신
9월 29일 15:04:58 KST까지 보호 대기를 둔다. 실제 배치는 이후 매시간 due 평가로
결정하며 보호 종료가 실행 예약은 아니다. 일반철도 TAGO provider PR #20은 별도
머지했지만 현재 키 단일 진단이 HTTP 403이어서 실제 운행 조회는 미확인이다.

## 검증 항목

배편 provider 호출 금지·누락/빈 응답·항구/날짜 상한, 좌표 없는 검색, 다중 유가 최신값,
운영 상태 비밀값 비노출, 한국 날짜/시각/요금/30km 경계, 버스 429/결과 무효화,
배편 선택 경쟁, GraphQL 오류, 모바일/데스크톱 화면을 단위/API/Playwright로 검증한다.
