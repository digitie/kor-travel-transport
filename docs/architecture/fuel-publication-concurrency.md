# 유가 저장과 통계 공개의 병행성

## 저장·준비·공개 경계

원본 가격·최신 가격·수집 성공 상태는 기존처럼 한 트랜잭션으로 확정한다.
그 후 별도 트랜잭션에서 500행 스트리밍으로 통계 point 세대를 준비한다.
`fuel_statistics_points` 기본 키에 `generated_at`을 추가하여 기존 공개 세대와 준비 세대가
같은 주유소·유종 키를 덮어쓰지 않도록 한다. 같은 시각의 중복 준비만 세대별 잠금으로 직렬화한다.

원천별 공개 잠금(420061/420062)은 정규화·point 저장 뒤 마지막에 획득한다.
최신 state를 다시 읽어 오래된 세대의 역전 공개를 거절하고, 원본 수집 성공 시각이 바뀌었으면
준비 결과를 버린다. 작은 일별 집계와 공개 state를 한 트랜잭션에서 전환한다.
따라서 조회는 기존 완성 세대 또는 새 완성 세대를 읽는다. 통계 실패는 원본 성공을 취소하지 않고
기존 세대와 `update_pending`을 유지하며 다음 정상 수집에서 다시 시도한다.

이전 point 정리는 공개 commit 뒤 별도 트랜잭션에서 2,000행씩 수행한다.
현재 공개 세대보다 오래된 행만 대상으로 하고 PostgreSQL `SKIP LOCKED`로 진행 중인 행을 건너뛴다.
한 수집의 정리 시간은 15초 이내에서 다음 묶음 시작을 제한한다. 개별 문장의 기존 timeout은 유지한다.
새 세대·준비 중 세대는 삭제하지 않으며 정리 실패는 다음 수집이 이어서 처리한다.

## 조회·마이그레이션

지도 집계의 후보와 최저가 주유소 조회는 같은 SQL snapshot의 공개 세대를 사용한다.
일별 조회의 7일/KST 날짜·같은 날 마지막 성공·사라진 범주 제거 계약은 유지한다.
API DTO는 변경하지 않는다. `0029_fuel_statistics_generations`는 PK와 원천/세대 인덱스를
추가하고 lock 대기 5초를 적용한다. downgrade는 공개 세대만 남기고 구 PK를 복원한다.
원본 이력은 삭제하지 않는다. 수집 worker를 비운 상태에서 migration과 API/code-server를 함께 배포한다.
현재 운영 대상은 사용자 지시대로 Odroid NVMe이며 과거 n150 전용 지시보다 우선한다.

## 수용 기준·실측

- 준비 중 API는 기존 통계를 읽고 준비 실패 뒤에도 동일한 완성 세대를 읽는다.
- 같은 세대 중복과 다른 세대 순서 역전에서 PK 충돌·역전 공개·현재 세대 삭제가 없다.
- 통계 스트리밍 중 원천 공개 잠금이 비어 있고 마지막 공개 구간만 잠금을 보유한다.
- 원본 commit 뒤 통계 실패 시 원본 가격·성공 상태와 `update_pending`이 유지된다.
- 실제 PostgreSQL migration upgrade/downgrade/check, 전체 backend, 프런트와 live UI 검증을 수행한다.
- 동일 데이터량에서 준비/공개 잠금 시간, API 지연, CPU·메모리·정리량을 측정한다.
  실측 전에는 성능 개선 수치를 주장하지 않는다.
